# Portfolio capture

The portfolio is assembled from what already exists on the day content
freezes. Capture at the moment of change; do not plan to recapture later —
later the old state is gone.

## Capture set per milestone

Store under `docs/portfolio/<date>-<slug>/` with a one-line README each:

1. **Hero shots** — the most presentable screens, captured big (2x device
   scale). Favor wide compositions and sequences that read left-to-right;
   the target canvas is a 594x210mm spread (aspect ≈ 2.83:1).
2. **Before/after pair** — when the change replaces visible behavior, capture
   both sides at identical framing.
3. **Process shot** — the diagram, whiteboard, failed variant, or rejected
   design worth narrating later. Failures with a reason are portfolio gold.
4. **Clip** — 15–30s screen recording of the loop in motion, when motion is
   the point.
5. **Caption line (English)** — for every asset:
   `what this shows · what was hard · what the result was`, one line.

## Rules

- Never overwrite an old capture; date-prefix everything.
- Screenshots at the real target viewport. Zhangyan V3 captures at desktop
  browser size per the 2026-08-24 viewport decision; its V1/V2 archive assets
  stay mobile portrait. Prior Probability is desktop. UI language as it ships.
- Mark each capture set with its candidate spread slot (concept / system /
  process / outcome / reflection) so assembly is a sort, not an excavation.
