# Research decision

Evidence before adoption — but a playable prototype outranks a citation for
any question about feel.

## Six steps

1. **Local baseline first** — what does this project already do or assume?
   Read before searching.
2. **Narrow the question** — one decision, phrased so evidence could change it.
3. **Gather at the quick floor** — one credible primary source or one real
   implementation is enough by default. Escalate to triangulation only when
   the user asks for deep research or the decision is hard to reverse.
   For feel/experience questions, prefer proposing the smallest prototype
   over collecting more citations.
4. **Compare with this project** — external practice supplies boundaries and
   trade-offs, not universal constants.
5. **Classify**: Adopt / Borrow / Reject / Unknown. `Unknown` plus a smallest
   useful experiment beats a confident guess.
6. **Recommend** — one primary recommendation, at most one alternative.

## Honesty rules

- Keep sourced facts, project-specific inference, and user value judgments
  visibly separate in the write-up.
- Do not present research volume as certainty.
- Record the result once, in the project's decision log, only when the
  decision is material.
