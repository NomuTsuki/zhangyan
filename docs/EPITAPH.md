# 墓志铭 — 被删规则及其防御的失败

> 用途:某类失败复发时,先来这里查它当年的解法,再决定用最窄的形式恢复到哪里。
> 恢复原则:写进项目 AGENTS.md(具体),不恢复到全局 skill(通用)。
> 背景:本项目此前由约 30KB 的 project-co-leader-v2 治理体系管理(存于旧仓库历史),
> 2026-08 经三轮独立审查后重构为现行轻量体系。

| 被删的机制 | 它防御的失败 | 现在谁接手 | 复发时怎么办 |
|---|---|---|---|
| 五角色人格(co-leader/questioner/…) | 模型缺乏主动性、不追问 | AGENTS 内核"一次一个问题带推荐" | 在项目文件里加一条具体的追问场景 |
| 阶段交接七步仪式 + 理解力测验 | 用户在未理解时批准,后期返工 | $learning-handoff(教学不考试) | 对特定高风险交接手动要求讲解 |
| 每个实质回答后的四行反思块 | 模型误读简短回答 | 内核"两种解读实质分歧时先确认" | 无需恢复,该条已覆盖 |
| 轻/标准/全三模式 + 0-3 六维打分 | 小事重办、大事轻办 | DoD 按证据分级(能跑必跑) | 在 AGENTS 列出"本项目哪些事算大事" |
| 问题预算跨轮计数 | 连环轰炸式提问 | "一次一个问题"硬规则 | 无需恢复,模型本就无法可靠计数 |
| Disclosure/Question/Challenge 三分类 | 决策与告知混淆 | 内核"冲突时摊开说" | 无需恢复,分类名不改变行为 |
| Tier A/B/C 权限分层 + 十步更新事务 | 模型越权改记忆/多文件写乱 | AGENTS"必须问用户的事"清单 | 把出事的具体操作加进清单 |
| 30 字段参数记录规格 | 数值来历失传 | $tune-params 8 字段 | 对特定参数族临时加字段 |
| triangulated 默认证据地板 | 拍脑袋决策 | $research-decision quick 地板+原型优先 | 对不可逆决策显式要求 deep |
| Routine/Material/Critical 契约状态机 | 测试设计承载产品含义时被随意改 | 内核"失败后不许静默放宽/重生成基线" | 对高危模拟手动要求完整契约 |
| overview/ 衍生仪表盘维护义务 | 用户找不到入口 | README + COMPASS 直接可读 | 手动重写一次 START-HERE 即可 |
| Active Work Ledger 10 字段 | 跨会话工作丢失 | 4 字段版 + $reorient | 对长期并行工作流临时加字段 |
| 兔子刹车(先停一下 + 三选项) | 分心点子冲掉主线 | 内核"冲突时摊开说"部分覆盖 | 复发则以两句话形式恢复进 AGENTS |
| 人话降密层(两层表达/比喻/图示) | 用户读不懂技术输出 | **未删**——保留在"沟通偏好",只删了考试环节 | — |

## 全局教训(写给未来的规则作者)

1. 每条规则的单独合理性,不等于规则总和的合理性;每轮加载的每个字都在竞争注意力。
2. 负面规则("不要 X")不减少负载,只增加评估条款;能删机制就不要加禁令。
3. 模型做不到的事(跨轮计数、稳定打分、区分近义标签)写成规则只是装饰。
4. 验证义务必须点名具体动作(跑什么、贴什么),打标签义务不产生证据。
5. 同一规则出现两处即是 bug:双份曝光 + 版本漂移风险。
