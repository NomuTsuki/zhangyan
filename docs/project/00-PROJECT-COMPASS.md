# Project Compass

> 保存项目相对稳定的方向性判断。它是当前最优参考，不是不可质疑的命令。

最后复查：2026-08-14（V2 终态）

## 项目目的

完成一款可在手机竖屏环境运行的《掌眼》游戏本体，让玩家在古玩鉴定与交易博弈中通过证据、陈述变化和交易条件管理不确定性。

## V2 终态定位

V2 到此结束。它交付了一个可运行、可回放、采用单一数值权威的玩家试玩底座，以及漆器第一批手机人物／器物同屏展示壳。真正的物品真相拓扑、玩家推理工作台、双方人物认知、连续 NPC、D20 与长期平衡没有在 V2 实现，不得因出现在设计记录中而写成完成成果。

冻结标签名称为 `v2.0.0-player-prototype-freeze`；它是提交外部的 Git 引用，是否已经创建必须以 Git 现场为准。后续产品设计进入独立 V3 工作树；V2 Decision 与 Evidence 只作为历史输入，不自动成为 V3 当前规格。

## 目标用户或受众

- 当前直接验收者：指导老师；验收对象是可运行的游戏本体。
- 最终玩家画像尚未确认，不把“老师验收”误写成长期目标用户定义。

## 核心价值或体验

玩家不是猜表情或做真假二选一，而是在有限行动点和信息不对称中，把不可验证的故事逐步转化为可核验的证据和有成本的承诺。玩家既在辨物，也在识人；NPC 同样只能根据自己看见的器物信息和玩家已经表现的行动形成可能出错的判断。

## 成功标准

- 能独立走完接案 → 检测与询问交叉调查 → 交易处置 → 客观结果与判断质量复盘的核心闭环；
- 玩家能说清证据簿与行动入口的职责区别；
- 玩家能区分“器物证据、对人物的判断、当前关系状态和成交意愿”，并理解它们可以朝不同方向变化；
- NPC 状态变化可追踪、可解释、可复现；
- 按“玩法完整度 → 视觉效果 → 技术实现 → 文化内容”的顺序逐层提高完成度。

## 不可牺牲原则

- 器物真相、双方对器物的认知、双方对彼此的认知、NPC 陈述、NPC 画像和局内状态分层；
- 真人玩家的内心不由系统自动定义；NPC 只能从玩家已经表现的行动形成可能出错的临时判断；
- 证据优先于情绪读取，结算不能退化为真假二选一；
- UI 不直接决定 NPC 结果，正式结果必须来自可测试的规则链路；
- 技术路线未验证前，不因单一经验或传闻作不可逆选择。

## 硬约束

- 2D、手机竖屏、最终载体为通过微信内网址打开的普通响应式 H5 网页，不是微信小游戏；
- 当前采用标准 Web 技术，Unity/团结引擎不是必经步骤；
- 计划周期约 7 周、210 小时；
- 内部计划目标是尽量在 `2026-10-20` 前完成作品集文书；这是当前收敛与排期目标，不冒充已经核实的院校外部提交截止日；
- 项目组负责游戏从设计到开发，老师负责建议和指导；
- V2 不再继续产品迭代；“漆器客观真相与证据拓扑”作为未完成依赖交给 V3 重新定义，人物认知、D20、议价和长期平衡仍不得越过这一前置结构提前定型。

## 明确非目标

以下是 V2 冻结范围中的明确非目标：

- V2 没有接入真实市场价格数据库或完整经济系统，只用游戏内量化价值、成交条件和检测成本表达客观得失；
- V2 没有接入生产 API、正式登录、云存档或大量正式内容；
- V2 没有用视觉精修替代玩法闭环验证。

## 重新讨论触发条件

- 新证据直接否定核心价值或受众假设；
- 约束、成本或项目范围发生实质变化；
- 已批准的成功标准无法被可行方式验证。
- 指导老师或验收规范把最终入口从普通网页 H5 改为微信小游戏，或明确要求某个引擎工程；
- 技术样片证明当前 Web 路线无法满足性能、包体、发布或关键交互要求。
