# System Map

> 描述项目当前的整体理解、职责边界和关键流动，不展开逐文件施工细节。

最后复查：2026-07-24

## 主要组成部分

| 组成部分 | 职责 | 当前状态 |
|---|---|---|
| 玩家 UI | 手机竖屏调查、证据簿、NPC 交流、交易与复盘 | React 版与单文件 HTML 均已跑通完整首案 |
| 游戏规则核心 | `WorldState`、合法行动、共享行动点、证据、NPC、交易与结算 | 多轮纯规则切片已实现并通过自动测试 |

## 关键流程或信息流

```text
固定物品真相 + 独立 NPC 认知档案 + seed
→ 玩家在 6 点共享预算内观察 / 询问 / 对质 / 送检 / 折价
→ 证据链和 NPC 四状态逐轮累计
→ NPC 候选行为发散、过滤、评分并收敛为一次回应
→ 玩家继续调查或执行购买 / 拒绝
→ 客观交易结果 + 仅依据可见信息的判断质量
→ 局末状态变化图、公式与完整回放
```

证据簿是只读信息仓库；进入证据簿不会提供行动入口，返回原页面后再由玩家决定下一步。

## 边界与依赖

- 物品客观真相决定观察结果和最终真实价值；NPC 回应与底价只读取独立认知档案和当前状态，不能偷看物品真相；
- 判断质量只读取玩家可见物证、检测和陈述信号；客观得失才读取隐藏真相；
- 同一次 NPC 回应生成的结构化信号与展示用陈述卡只计权一次；
- seed 只影响允许的幸运证据和近分候选扰动，不改变隐藏真相、固定成本或公式；
- H5 是交付载体描述，不等于必须采用 Unity；微信内网页、微信小游戏与 Unity Web 构建仍是不同发布路线。

### 已批准、尚未实现的双边信息边界

- 后续目标状态在现有真相隔离上增加玩家后验、NPC 后验和共享信息层，见 [DEC-007](decisions/DEC-007-dual-belief-and-strategic-disclosure.md)；
- 玩家私有证据只有在用于质询、对峙或共同检测后才进入共享信息；共享后双方按各自专业度重新解释；
- NPC 允许真诚误记或误判，但不能故意生成与自身已知信息相反的事实陈述；
- 共享证据负责更新 NPC 主观估值，四状态主要负责改变谈判档位、让步和接受条件；
- 初始开价不再承担唯一价格锚点职责，NPC 可以高估、低估、给出区间或无法开价；
- 立即买断等交易条件可以重新分配不确定性风险，但其是否健康仍由 [HYP-004](hypotheses/HYP-004-dual-posterior-disclosure.md) 验证。

## 关键接口或交接点

- `PlayerAction` 是 UI 与规则核心之间的唯一行动输入；
- `createInitialWorldState → resolveTurn / replayActions → WorldState + Settlement` 支持无 UI 测试和完整回放；
- 案件内容通过 `CaseDefinition` 配置进入规则层；
- 玩家 UI 与开发调试表面分离：手机画布只显示玩家应知信息，精确系统过程位于桌面侧栏；
- 买下与拒绝是零行动点终局动作，保证共享预算耗尽后仍能完成一局。

## 容易耦合或失控的区域

- 将 NPC 回应直接绑定隐藏真相，会造成“NPC 全知”和判断评分泄题；
- 在 UI 中重新增加结果特判，会破坏纯规则回放和 React/独立 HTML 一致性；
- 免费或无机会成本的送检会成为支配策略；
- 过早扩展第二案件、真实市场数据库或正式美术，会掩盖当前平衡和理解度未知；
- TypeScript 主规则与独立 HTML 客户端目前仍是两份实现，后续必须保留差分测试或统一规则源。

## 当前未知

- 玩家和老师能否清楚理解“客观结果”与“判断质量”共同构成的胜负；
- 6 点预算、送检 `2 AP + 10`、固定折价 60 与当前 NPC 阈值是否平衡；
- 线索的温和导向是否足够，是否仍存在唯一最优路线或支配策略；
- 最终发布入口是通用网页、微信内网页还是微信小游戏，以及是否有采用 Unity 的实际必要；
- 首案真实文化内容、器物知识和数值是否需要专家校订。
