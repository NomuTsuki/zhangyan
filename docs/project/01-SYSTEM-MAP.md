# System Map

> 描述项目当前的整体理解、职责边界和关键流动，不展开逐文件施工细节。

最后复查：2026-07-22

## 主要组成部分

| 组成部分 | 职责 | 当前状态 |
|---|---|---|
| 低保真 UI | 手机竖屏页面、导航、反馈和可点击闭环 | React 版与单文件 HTML 均可运行 |
| 游戏规则核心 | PlayerAction、Evidence、NPCState、结算和事件日志 | 首个专业对质规则切片已接入两套 UI |
| 案件内容 | 器物真相、NPC 认知与陈述、证据、Storylet | 首个漆木首饰盒案例为 Mock 数据 |
| 调试与可解释性 | 显示四项精确状态、delta 原因、固定 seed 和回放 | 桌面独立侧栏已显示 seed、四项 delta、处理链与触发原因；完整回放待实现 |
| 构建与交付 | 生成可在手机浏览器访问的 H5 并提供游戏本体 | Web 原型已在线运行；最终引擎未决定 |

## 关键流程或信息流

玩家输入 → 结构化 PlayerAction → 规则结算 → NPCState 与陈述历史 → 页面表现 → 交易处置与复盘。证据簿只读；观察页是当前调查阶段的行动枢纽。

## 边界与依赖

- H5 是交付载体描述，不等于已经选择 Unity 或标准 Web 框架；
- “微信内网页”与“微信小游戏”是不同发布目标，必须先明确入口再决定工程路线；
- 当前在线地址用于访问已构建的 Web 原型，不代表必须采用当前托管服务作为最终发行渠道。

## 关键接口或交接点

- `PlayerAction` 是 UI 与规则系统之间的唯一行动接口；
- `initialState + actionSequence + seed → finalState + eventLog` 是规则可测试性的目标接口；
- 案件内容通过配置数据进入规则层，不硬编码到正式 UI 组件。
- 玩家 UI 与开发调试表面分离：手机画布只显示玩家可理解、可操作的信息，规则明细放在宽屏侧栏。

## 容易耦合或失控的区域

- 让温和/强硬长期停留在 UI 特判中，会重新造成表现层与规则层耦合；
- 把微信小游戏、Unity Web 和浏览器 H5 混为同一概念，会过早锁定错误工具链；
- 同时推进价格平衡、视觉精修和规则引擎会稀释当前玩法验证。

## 当前未知

- 最终发布入口是通用网页、微信内网页，还是微信小游戏；
- 标准 Web/H5 与 Unity 路线在团队学习成本、手机启动速度、包体和发布流程上的实测差异；
- 温和、专业、强硬三种态度是否存在明显支配策略；
- 当前 Storylet 阈值在更多初始状态下是否稳定可解释。
