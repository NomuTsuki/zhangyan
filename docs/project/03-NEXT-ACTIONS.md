# Next Actions

> 推荐能够以较低成本减少最大重要未知、风险或阻塞的行动，而不是机械维护功能清单。

更新时间：2026-07-31

## 推荐主路径

把 `掌眼_高保真教师演示.html` 交给老师进行一次 10—15 分钟的无讲解试玩。先观察老师如何理解界面，再解释规则；不要一开始展示开发公式。

## 这次试玩只验证五件事

1. 老师能否自行完成观察、收证、询问、报价和结算；
2. 老师能否说清“仅自己掌握”和“双方共享”的区别；
3. 看到 `80 → 65` 时，老师能否理解是公开证据触发卖家重估；
4. 老师能否区分调查行动点和议价容量；
5. 老师能否用自己的话解释综合等级与四个分项。

## 试玩时应记录

- 第一次犹豫超过 5 秒的位置；
- 误点、找不到下一步或错误理解的文案；
- 老师主动提出的问题；
- 哪些开发侧解释必须由我们口头补充；
- 老师认为最像游戏和最不像游戏的部分；
- 老师对视觉风格、器物插画和文字观察方式的直接反馈。

## 完成标准

- 老师实际走完至少一局；
- 不依靠开发栏完成主要任务；
- 对上述五项分别记录“理解 / 部分理解 / 未理解”；
- 将界面问题、规则问题和参数问题分开记录；
- 只根据真实反馈决定下一轮，不用猜测继续扩功能。

## 结果分支

### 若主要是界面问题

优先调整信息层级、文案、按钮位置和反馈时机，不改规则核心。

### 若主要是规则问题

先写出具体失败情境和预期，再修改规则与回归测试；不在界面中用特判掩盖。

### 若老师可以顺利理解

进入普通网页 H5 发布准备：

1. 选择静态托管；
2. 配置 HTTPS 地址；
3. 用真实微信聊天链接打开；
4. 检查字体、滚动、软键盘、分享和返回行为；
5. 再决定是否需要公众号 JS-SDK 等平台能力。

## 暂时不做

- 不迁移 Unity；
- 不申请微信小游戏 AppID；
- 不制作第二案件；
- 不扩展长期经济和真实市场数据库；
- 不为当前低价值教学器物制作写实局末讲解图；
- 不把当前参数称为已经平衡。
