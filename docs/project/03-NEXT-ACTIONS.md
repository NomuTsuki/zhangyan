## 推荐主路径

在以 `.worktrees/v2-bootstrap` 为项目根目录的新 Codex 顶层任务中，先完成一次只读 V2 启动审查，再为第一项核心产品工程编写独立实施计划。

启动审查必须依次回答：

1. V1 冻结提交、tag、worktree、原工作区未提交资产与 V2 分支之间是否保持清楚且可回滚；
2. 生产规则、案件配置、数值实验台、历史低保真、生成单文件、玩家显示投影和测试分别在哪里定义数值；
3. 哪些位置是当前生产权威、实验参数、复制实现、生成结果或仅用于测试的例证；
4. 当前 `AGENTS.md`、V2 配置、可调用 Skill 清单与 Agent 治理依赖是否正确加载；
5. 哪些冲突会阻塞数值权威源统一，哪些只是后续非阻塞清理。

审查完成后，Agent 必须主动提醒用户：**统一数值权威源已经获批，是 V2 第一项核心产品工程。**

## 完成标准

- 输出一份逐模块数值来源表，至少覆盖规则核心、案件内容、NPC、定价、结算、实验台、UI 投影、单文件和测试；
- 每项标明当前权威、消费者、已知复制、耦合关系和迁移风险；
- 明确 V1 冻结资产、原工作区 31 项未提交资产和 V2 可修改表面，任何未知来源都不被自动吸收；
- 核验 V2 Skill 实际可调用；若 `project-agent-governance` 仍未注册，只报告和诊断，不假装调用；
- 给出统一数值权威源的分批实施计划、回滚点和验证门槛，但不在审查中直接实施重构。

## 审查后的第一项核心工程

统一数值权威源的已批准完成定义保持不变：

- 每个数值模块只有一个明确的生产权威源；
- 高保真、低保真、数值实验台、生成单文件和测试不再各自复制核心公式；
- 实验参数、生产参数、显示投影和调试数据有明确边界；
- 单文件由构建生成并能追溯到源提交；
- 回归测试区分代码一致性、设计例证、批量平衡和真人体验，不再用“测试通过”代替“玩法正确”；
- 迁移能够分批回滚，并保持 V1 冻结版不变。

## Agent 治理分支

- 如果新任务能够调用 `project-agent-governance`：只预览最小能力与责任拓扑；创建持久 Agent、扩大权限或改变决策权仍需另行批准；
- 如果仍不能调用：先诊断 Skill 注册与项目发现机制，基础 V2 Co-Leader 可继续工作，但不能声称 Agent 治理已经采用；
- 临时、只读、边界明确的子 Agent 可以用于审查，但必须由当前主 Agent 汇总结论并承担责任。
