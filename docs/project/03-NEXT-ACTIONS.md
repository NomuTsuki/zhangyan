# Next Actions

> 推荐能够以较低成本减少最大重要未知、风险或阻塞的行动，而不是机械维护功能清单。

更新时间：2026-07-22

## 推荐主路径

把温和与强硬也接入现有规则接口，然后做一次 3—5 人的小规模试玩，重点观察玩家是否理解三种态度的代价以及是否出现明显支配策略。

## 为什么现在做

专业分支已经证明规则链路可运行。当前最大玩法未知从“能不能算”转为“不同选择是否真的形成策略，而不是只有一个正确按钮”。先补齐三种态度比继续加页面或美术更能降低核心不确定性。

## 要减少的核心未知或风险

- 温和与强硬目前只是文案反馈，尚未形成真实数值后果；
- 当前专业分支可能被玩家理解为唯一正确答案；
- Storylet 阈值只在一组初始状态下验证，尚不清楚是否容易误触发或永不触发。

## 完成标准

- 三种态度全部输入同一个 `resolveAction`，并输出可解释的 `ActionResult`；
- 温和、专业、强硬在至少两项状态变化或 Storylet 结果上有清楚差异；
- 自动测试覆盖三分支、阈值边界与相同输入可复现；
- 3—5 名体验者无需口头提示完成一次行动选择；
- 记录态度选择、理解原因、是否改选和主要困惑，据此保留或调整参数。

## 前置条件

- 继续把当前参数视为工作样例；
- 暂不增加价格平衡、第二案件或正式美术；
- 不需要先决定 Unity 或标准 Web/H5。

## 结果分支

- 如果三种态度各有明确用途：再增加第二条证据或第二个 NPC 行为，验证组合空间；
- 如果专业成为明显支配策略：先调整信任、压力、控制感副作用与 Storylet 条件；
- 如果玩家看不懂原因：先改行动前提示和回应日志呈现，再扩内容。

## 暂时不做

- 正式价格与交易平衡；
- 大量器物内容、生产 API、登录与云存档；
- 在分发入口未澄清前迁移到 Unity。

## 备选行动

让同事明确其所说的“微信 H5 小游戏”是微信内网页还是微信小游戏，并记录目标入口、提交主体、包体和上线审核方式；该确认不阻塞玩法迭代。
