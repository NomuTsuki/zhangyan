# Architecture / Design Challenge: 线性阶段与态度按钮阻碍核心玩法

Status: Resolved

日期：2026-07-23

## 观察

现有原型把观察、证据、态度行动、NPC 回应和交易拆成单向阶段。玩家行动主要被压缩为温和、专业、强硬三种态度，无法表达“检查哪里、问什么、引用哪条证据”，也无法让证据链和 NPC 状态在多轮交叉行动中持续变化。

同时，现有结算没有基于器物真实价值计算客观得失，“送检后再议”若无成本会成为支配策略。

## 受影响的现有决定

- Project Compass 中原有的线性闭环表述；
- DEC-002 中“当前暂不进入价格与交易数据”的范围；
- 当前三态度规则切片与小规模试玩计划。

## 证据

- 用户 2026-07-23 指出检测与询问应交叉进行并共用行动点；
- 用户要求案件存在量化后的客观真相与价值；
- `prototype/app/page.tsx` 当前按单次态度决定推进和交易入口；
- 现有测试只验证单次态度结算，未验证多轮证据与 NPC 状态演化。

## 不处理的后果

继续扩展当前 UI 会把错误的线性阶段固化到更多页面；重复态度无法支撑足够的行动点；观察、询问和交易都可能产生死局或支配策略；试玩结果只能评价界面理解，不能验证真正的核心玩法。

## 可选方案

1. 在现有线性页面上继续增加分支和例外；
2. 改为共享行动预算的调查循环，并将客观结果与判断质量分层结算。

## 推荐

采用第二种方案。先制作无界面的规则样片，验证多轮行动、隐藏真相、量化价值、送检成本和结算，再重构 HTML。

## 需要用户拍板的问题

用户已批准调查与询问交叉、共享行动点、客观价值结算和送检必须付出代价。仍待确认客观结果与判断质量如何共同形成“本局胜利”，以及送检采用何种具体成本。

## 解决结果

核心方向已由用户在 2026-07-23 批准，形成 [DEC-003](../../decisions/DEC-003-integrated-investigation-loop.md) 与 [DEC-004](../../decisions/DEC-004-objective-outcome-and-judgment.md)。具体结算门槛和送检成本留待下一轮确认。
