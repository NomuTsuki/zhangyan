# DEC-008: 采用普通网页 H5 作为最终载体

Status: Active

日期：2026-07-31

## 当前决定

《掌眼》的最终载体是通过微信聊天、公众号文章或相似入口中的网址打开的普通响应式 H5 网页，而不是需要小游戏 AppID、微信开发者工具代码包和平台提审的“微信小游戏”。

当前正式开发继续采用标准 Web 技术。Unity/团结引擎不是必经步骤，也不为尚未出现的引擎需求提前迁移。

本轮教师演示仍交付可离线双击打开的自包含 HTML；最终公开版本再部署到可访问的 HTTPS 地址。微信登录、JS-SDK 分享、支付等平台能力不属于当前核心闭环，只有确有需求时才分别确认公众号配置、授权域名和合规要求。

## 背景和问题

此前只确认“最终载体为 H5”，但“微信内网页”“微信小游戏”和“Unity Web 构建”曾被混用，导致正式技术路线无法关闭。2026-07-31，用户转述指导老师的明确答复：目标是前者，“和公众号链接的网页一样”。

## 考虑过的替代方案

1. 普通响应式 Web/H5，通过网址在微信内打开；
2. 微信小游戏，使用小游戏 AppID、开发者工具和平台发布流程；
3. Unity/团结引擎制作后再转 Web 或微信小游戏。

## 选择理由

- 与老师描述的实际打开方式一致；
- 当前游戏以二维插画、状态、文字和 UI 交互为主，标准 Web 已能覆盖核心需求；
- 团队没有 H5 或游戏开发经验，减少一套非必要引擎与平台工具链能降低学习和返工成本；
- 保留了后续按具体能力接入微信接口的空间，但不会让平台功能反向绑架当前玩法验证。

## 影响范围

- HYP-001 从“入口待确认”转为 Supported；
- 当前高保真版本使用 React、TypeScript、CSS、SVG 和单文件生成；
- 发布准备关注静态托管、HTTPS、移动端兼容和微信内浏览器实机验证；
- 不创建 Unity 工程或微信小游戏工程；
- 若老师改变入口，或出现 Web 无法满足的明确性能与能力约束，再重新比较技术路线。

## 当前信心

高。入口由指导老师明确，且现有 Web 原型已经证明核心交互可运行。最终托管、域名和微信内实机兼容仍需在公开部署阶段验证。

## 重新讨论触发条件

- 指导老师或验收规范明确改为微信小游戏；
- 出现必须依赖小游戏平台且普通网页无法合理替代的核心能力；
- 真实设备样片证明 Web 路线无法满足启动、性能、包体或关键交互要求。
