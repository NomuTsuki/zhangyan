# DEC-010：V1 先做最小交付修正，再正式封存

Status: Active

日期：2026-08-03

## 当前决定

给老师正式提交的 V1 主体以最新评分修正版为起点。当前可验证起点是提交 34f97e250c4dcf139e1ae2d3d536af7a0e36786b，并在独立分支 codex/v1-teacher-finalize 中收口。

采用已批准的方案二：

1. 只处理会破坏教师交付一致性、仓库可理解性或基础验证可信度的最小问题；
2. 补齐项目说明和演示说明；
3. 重新验证后封存 V1；
4. V1 不承担全量数值系统统一、第二案件、正式运营或低认知门槛自动化层的重构。

本决定只是批准收口边界。2026-08-03 本次预检没有修改游戏运行代码，也没有提交、合并、移动 main 或创建冻结标签。

## 已确认的验收事实

- 老师能够找到关键入口、理解证据公开并完成交易，核心玩法循环的基本可理解性已经由用户确认；
- 这项确认只覆盖老师对当前演示闭环的理解，不代表一般目标玩家、不同案件和不同难度已经完成真人验证；
- 教师提交应明确区分：已实现、自动化验证、真实浏览器验证、仍待验证和 V2 规划。

## 选择理由

- 当前评分修正版已经修复旧客观总分问题，并有较完整的自动化和浏览器证据；
- 完整测试仍保留一条已知低保真静态断言失败，仓库根工作区也混有历史低保真改动、对齐文档和周报文件；
- 在封存前做有限收口，可以提高交付可信度，同时避免把 V2 的结构性工作偷渡进 V1。

## V1 最小修正准入条件

只有同时满足下列条件的改动才可进入 V1：

- 问题能在当前教师交付路径或仓库说明中复现；
- 不改变已批准的核心玩法、评分方向或信息边界；
- 有明确、有限的验证方式；
- 不要求统一全部数值权威源或新增正式内容。

不满足上述条件的问题进入 V2 风险和行动清单，不在 V1 临时扩写。

## 影响范围

- V1 定稿只在 codex/v1-teacher-finalize 工作树推进；
- 原 codex/hifi-teacher-demo 工作区的未提交内容先保全和分类，不自动合并；
- V1 封存完成后，以一个明确提交和冻结引用作为老师材料与 V2 分叉的共同来源；
- 冻结前仍需另行执行并验证最小修正、项目说明、演示说明和打包。

## 当前信心

高。用户已明确批准方案二，并确认教师正式提交主体是最新评分修正版。

## 重新讨论触发条件

- 最小修正需要改变核心规则或废弃评分修正版的大量工作；
- 教师提交规范新增必须功能；
- 验证发现评分修正版存在阻断核心闭环的数据损坏或安全问题；
- V1 修正范围开始演变为结构性重构。
