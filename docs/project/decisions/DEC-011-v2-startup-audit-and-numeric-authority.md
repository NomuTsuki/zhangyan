# DEC-011：V2 启动先审查仓库，再提醒并统一数值权威源

Status: Active

日期：2026-08-03

## 当前决定

V2 首次实际启动时，必须按以下顺序执行：

1. 先由 Agent 对 V1 冻结点、Git 分支与工作树、未提交内容、项目 Agent 框架，以及生产规则、实验台、单文件、测试和文档之间的权威边界做只读审查；
2. 审查完成后，Agent 必须主动告诉用户：统一数值权威源已经在 2026-08-03 获得批准，是 V2 的第一项核心产品工程；
3. Agent 同时报告审查发现的冲突、保留资产、迁移建议和验证门槛；
4. 如果审查没有发现会跨越已批准边界的新冲突，即按该决定制定和执行数值权威源统一计划；若发现重大冲突，则以 Challenge 形式请求用户决定。

仓库审查和 Agent 框架迁移是 V2 的启动前置条件，不与“第一项核心产品工程”的称谓冲突。真正进入产品内核后的第一项工程仍是统一数值权威源。

## 什么叫统一数值权威源

目标不是立即平衡所有参数，而是先结束同一概念在多处重复实现、可能漂移的状态：

- 明确物品真相、证据、玩家后验、NPC 后验、NPC 状态、定价、议价容量和结算各自唯一的生产规则来源；
- 高保真 UI、低保真调试界面、数值实验台和自动测试通过明确接口读取规则，不再各自复制核心公式；
- 实验参数与生产参数分层，实验台不能被误写成正式玩法权威；
- 单文件交付由可追踪构建生成，不把手工复制品当作另一个规则源；
- 每项数值都能追溯到已批准决定、暂定工作参数或待验证假设。

## 为什么把它放在 V2

- V1 的目标是让老师结合演示完整理解项目，不适合在封存前做大范围架构改写；
- 当前 TypeScript 规则、实验台、低保真单文件和生成物之间仍存在历史重复与静态断言漂移；
- 先统一权威源，后续才能可靠地做多案件、自动化、低认知门槛层、批量调参和更严谨的真人试玩。

## V2 审查最低范围

- 确认 V1 冻结提交、标签、分支和教师交付包之间的一致性；
- 检查所有 dirty、untracked、救援引用和历史工作树，不默认丢弃；
- 列出每个数值模块的当前定义位置、调用者、测试和重复实现；
- 区分生产规则、实验规则、显示投影和调试信息；
- 审查 AGENTS.md、项目负责人 Skill、Agent 配置和权限边界，避免新旧 Agent 架构互相覆盖；
- 给出可分批迁移、可回滚、每批有测试证据的方案。

## 自动触发语义

“自动”是项目流程触发器，不是后台常驻程序：当未来任务明确进入 V2 启动时，负责 Agent 在修改产品代码前执行上述审查，并在审查结束的同一轮主动提醒用户，不依赖用户再次记起这项决定。

## 当前状态

已批准，尚未启动。V1 仍处于定稿准备阶段；本轮不创建 V2 分支，不改造 Agent 框架，也不统一数值代码。

## 当前信心

高。用户已在 2026-08-03 正式批准该建议和触发方式。

## 重新讨论触发条件

- V1 尚未形成可识别冻结点；
- V2 启动审查发现权威源统一会推翻核心价值或重大已批准规则；
- 新 Agent 架构要求扩大权限、覆盖现有工作或改变用户的单一负责人入口；
- 技术样片证明当前 Web 规则核心无法作为正式运行权威。
