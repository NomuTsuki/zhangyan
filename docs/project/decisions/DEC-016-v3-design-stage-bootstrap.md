# DEC-016：V3 从物品真相拓扑设计阶段启动

Status: Active

日期：2026-08-14

## 决定

V3 从 V2 annotated tag `v2.0.0-player-prototype-freeze` 的精确提交 `32db763e2fcdcfcb5f090b38405498105d904e19` 建立独立分支 `codex/v3-object-truth-topology` 与独立工作树。

首次提交只建立 V3 权威记录并迁入带来源和 SHA-256 的设计证据，不修改产品代码。V3 当前处于 **Design**，不是 Implemented 或 Verified。

眼前只收敛物品侧：固定客观真相、证据／推理依赖、玩家知识图、玩家后验以及继续调查或收手的后果。NPC 深层认知、人物画像、连续对话、D20 与新议价不进入 V3 启动批次；是否作为申请季后的第二部分重开，留待未来决定。

## 对 V2 的继承分类

### Adopt

- V2 冻结点、V1 冻结边界与独立 worktree 隔离；
- 单一数值权威、确定性 seed／replay、玩家／开发投影隔离和可追溯构建原则；
- 客观真相不被角色认知或 UI 改写；
- 自动验证、真人体验、平衡、文化和视觉证据分开报告。

### Borrow

- V2 的器物后验、行动预算、估值区间和能力／客观结果双轨只作为可复用结构；实际公式、固定真相类别、A／D／N 与经济终局必须在 V3 重新证明；
- DEC-014 的证据图、人物表现与洞察只保留领域边界，不继承其未实现产品规格。

### Reject

- 把 V2 的五个观察热点、21 条候选 evidence 或平铺似然表当成 V3 深度指标；
- 把完整作者依赖图直接显示给玩家；
- 把客观真相、证据、玩家所处位置和价格压成同一种节点；
- 因启动 V3 就同时实现五种拓扑、NPC、D20、议价和正式美术。

### Unknown

- 中间节点的最终语义；研究推荐“可被证据支持／反驳的鉴定主张”，仍需用户确认；
- 第一切片的经济终局、低估／高估后果和玩家最终承诺；
- 玩家图是自动、手动还是混合，以及数字显示强度；
- 第一种简单拓扑的完整器物问题、节点数量与验证方法；
- `2026-08-26` 的精确完成定义是否可行。该日期是内部计划候选，不冒充外部硬截止日。

## 为什么先解决两件事

在节点语义未定时，画五种拓扑只会得到漂亮但含义混杂的图；在经济终局未定时，也无法判断一项调查究竟减少了有用不确定性，还是只让数字变化。

因此第一决策门按依赖顺序为：

1. 图上的中间节点是什么；
2. 第一切片最后让玩家为哪一种判断和经济选择承担后果。

两者确认后，才把用户的第一种简单拓扑写成纸面规格；规格获批前不进入产品实现。

## 设计原则（已采用的边界，不是具体实现）

- 客观真相从开局固定，沿图变化的是玩家掌握的证据和相信程度；
- 定性身份与定量价值都要表达，但不要求玩家手算贝叶斯公式；
- 核心理解不能因一次随机失败永久消失；风险检定可以改变成本、精度、效率或器物状态；
- 非最优调查顺序仍应允许完成一局，较好顺序可以带来更高信息价值；
- 玩家侧图帮助记忆、解释关系和规划方向，不显示隐藏答案轮廓、真实 AND／OR 门或唯一最优动作；
- 前中期可以较快降低不确定性，后期随着容易信息减少而转为小步承担成本与风险；这是节奏升级，不是另起一套连续检定游戏。

## 授权边界

本决定授权 V3 文档与证据启动，不授权产品代码、数值公式、案例内容、美术制作、提交之外的 push／deploy／公开发布，也不授权修改 V2 tag 或 V1 资产。

## 完成与验证

V3 启动完成只表示：分支来源可复现、证据逐字节迁入、项目记录清楚、产品 diff 为 `0`，并且下一决策门明确。它不证明拓扑可玩、UI 可懂、经济成立、作品集完成或截止日期可达。

## 重新讨论触发条件

- 用户不同意“鉴定主张”作为中间节点；
- 第一切片终局改变，导致调查价值、停止或高估代价语义变化；
- 无答案玩家无法理解候选玩家图，或图稳定泄露答案；
- `2026-08-26` 候选范围无法在时间／美术／测试资源内形成完整成果；
- 新证据表明 V2 技术底座不适合拓扑、回放或移动端呈现。
