# DEC-023：V3 正式产品代码前先通过作者、玩家与领域三道证据门

Status: Active

日期：2026-08-20

## 当前决定

V3 第一陶瓷切片在修改正式产品代码前，按以下依赖顺序推进：

1. 撤回被误升格的举例，完成作者模型独立结构复核与确定性场景演算；
2. 通过限定范围的领域复核，并由用户共同批准作者纸面规格；
3. 玩家侧先验证“事实—当前解释—开放问题—调查方向”的知识工作台微循环，并让它通过无答案真人测试；
4. 研究并记录首案数值来源，批准 Critical 模拟合同后再演算 Experimental 阈值、迟滞、价值、调查成本与市场节奏；
5. 数值模拟之后再扩成从接物到局末揭示的整局低保真原型，并让整局通过另一份无答案真人测试合同；
6. 完成 V2 `Adopt / Borrow / Reject` 技术审查与 V3 实施计划后，再由用户明确批准正式产品代码开工。

正式产品代码前允许使用与产品实现隔离的确定性求解器、模拟脚本和可丢弃交互原型。它们是验证工具，不自动成为生产架构或已实现玩法。

第一玩家侧原型采用以下方向：

- 玩家知识图由系统整理本局已知事实和允许看见的关系；玩家确认关注、暂存判断并决定继续或收手，不要求手工搭建作者图；
- 局中默认用自然语言说明主要连贯解释、变化原因和剩余未知；粗概率由玩家按需展开，不显示精确边权、似然或阶段阈值；
- 常驻层显示当前问题缺口和若干调查方向，更具体的行动与救援提示由玩家主动展开；第一切片不预设自动“卡住”判断；
- 作者完整图、隐藏证明门和完整后验轨迹只在成交或挂牌期满后随局末揭示显示。

## 2026-08-23 后续澄清

上述“自然语言首层”在首轮文字／面板原型被用户否决后，已由 [DEC-026](DEC-026-v3-progressive-player-knowledge-map-and-current-best-hint.md) 收窄为渐进显影地图上的就地解释；文字不再承担玩家认知结构的主骨架。“常驻方向、提示按需加深”继续有效，并具体化为问题级探索前沿、按需行动类别和玩家主动请求时的当前最优调查。该最强提示只按本局当前已知信息计算，不读取作者隐藏真相或保证结果。

领域复核只阻断材料、检测能力、保护与价值因果上的不可能、越权或严重误导；器物个性、证据分布、关卡节奏和视觉选择仍由游戏性与用户批准边界决定。

## 背景和问题

作者模型已经形成 12 个核心候选解释包和三档结果候选，但仍未经过独立结构复核、正式场景演算、领域复核或玩家验证。如果直接进入产品实现，规则错误、信息泄露和无意义确认都可能被界面与代码固化。

同时，用户长期使用“比如／比方说／举例”解释概念。此类措辞不等于授权采用具体内容；项目曾错误地把一个反证举例升格为固定验收案例，因此需要先恢复授权边界。

## 考虑过的替代方案

1. 直接制作完整玩家界面，再边实现边修作者规则；Reject，会把作者、玩家和数值问题混在一起；
2. 只做玩家知识图，不验证停手、挂牌和市场闭环；Reject，不能在产品代码前证明完整一局；
3. 完全由系统生成玩家报告；Borrow，信息清楚但可能让玩家退化为阅读者；首案保留玩家确认与停手责任；
4. 要求玩家手工搭建整张图；Reject for first slice，移动端操作、教学和误连恢复成本过高；
5. 只用 Agent 或作者自测替代真人；Reject，结构检查不能证明玩家理解、能动性或趣味。

## 选择理由

- 先微循环后整局，可以先分辨信息表达问题，再验证完整停手与经济闭环；
- 系统整理、玩家确认保留了自由调查和认知责任，同时避免把移动端拖图当成推理深度；
- 自然语言首层与按需粗数兼顾可解释性和停手支撑，降低把概率当进度条的风险；
- 独立结构、领域和真人三类证据分别回答“规则是否自洽”“因果是否可信”“玩家是否读懂”，不能互相冒充；
- 隔离验证代码允许提前发现模型错误，又不把试验性求解器偷渡成生产系统。

## 影响范围

- DEC-017—022 的真相、三档结果、手动停手、三轨经济和开放调查边界不变；
- 玩家侧从完全 `Unknown` 进入已批准的验证方向，但具体布局、概率组件、提示文案、交互细节和视觉风格仍为 `Unknown / Prototype required`；
- DEC-018 数值仍为 Experimental；任何模拟前必须提交 Critical 验证合同，不因本决定自动批准具体值；
- H5 路线继续 Active；V2 代码只能在后续技术审查中逐项 Adopt／Borrow，旧内容、NPC 和旧数值不能静默回流；
- 无答案真人测试、领域复核结果和作者规格用户批准是正式产品代码开工的必要证据。

## 当前信心

高：开发依赖顺序、玩家侧首轮方向和三类验证职责由用户逐项确认，并与既有研究和 DEC-017—022 相容。具体 UI、粗概率组件、测试合同和 Experimental 数值仍须原型或研究决定。

## 重新讨论触发条件

- 玩家确认在微循环测试中只是无意义按钮；
- 文字为主、按需粗数仍被理解为市场保证或阶段进度条；
- 常驻方向提示稳定泄题，或完全不能防止无目标游荡；
- 低保真真人测试证明“先微循环后整局”不能有效隔离问题；
- 领域复核要求改变核心证据链或检测因果；
- V2 技术审查发现 H5 或现有底座无法承载已批准体验；
- 用户改变正式产品代码开工门或验证责任边界。
