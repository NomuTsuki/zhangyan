# EXP-002: 最小 NPC 规则切片验证

日期：2026-07-22

## 测试了什么

验证“专业 + 指出修复历史矛盾 + 现代胶痕”能否从固定 `NPCState + PlayerAction + Evidence + seed` 生成四项状态、阶段、原因日志与 NPC 改口，并让 React 和单文件 HTML 使用同一结算结果。

## 方法

- 建立独立类型与规则模块，UI 只构造行动并读取 `ActionResult`；
- 使用 seed `20260722` 运行首案工作参数；
- 自动测试确定性、Storylet 结果、0—100 边界、缺失证据和非法 seed；
- 执行生产构建与 ESLint；
- 在 390 × 844 浏览器视口走完“观察接口 → 收录证据 → 行动 → 回应”主路径，检查布局、手型指针与运行日志。

## 观察结果

- 工作样例稳定输出：压力 `26→54`、信任 `58→61`、成交意愿 `72→66`、控制感 `68→42`；
- 阶段由 relaxed 变为 cautious；
- 达到压力、控制感、成交意愿阈值后触发部分承认修复可能；
- 构建、5 项自动测试与 ESLint 全部通过；
- 390 × 844 下无横向溢出，浏览器控制台无错误；
- 收录证据后正确关闭特写并回到观察页，由玩家自行点击行动。
- 已保存并发布为 Sites 第 7 版，继续沿用现有演示地址。

## 对决定或假设的影响

- 证明 UI 与规则可以通过 `PlayerAction → ActionResult` 解耦；
- 支持继续沿 Web/H5 原型验证玩法，但仍不足以决定最终引擎；
- 下一项最大未知已转为三种态度是否形成可理解且无支配策略的选择。

## 结论的局限

- 只验证一条专业分支和一组初始状态；
- seed 已纳入接口但当前切片没有随机采样；
- 参数与阈值尚未经过真人试玩和平衡；
- 证据发现、交易与复盘仍含 Mock。

## 下一步

让温和与强硬进入同一规则接口，并用 3—5 人试玩数据判断是否需要调整副作用和 Storylet 阈值。
