# EXP-004: 三种态度规则分支验证

日期：2026-07-22

## 测试了什么

验证温和、专业、强硬能否通过同一条 `PlayerAction → resolveAction → ActionResult` 链路产生真实、可解释且可复现的差异，并由 React 版和独立 HTML 版共同消费。

## 方法

- 以同一初始 NPC 状态、同一条“现代胶痕”强证据和固定 seed `20260722` 分别结算三种态度；
- 为普通部分承认与强硬防御性改口设置独立 Storylet 条件；
- 让收集首条证据和每次提交行动各消耗 1 行动点；
- 同步 React 与独立 HTML 的回应、后续按钮、交易风险、关系影响和桌面调试输出；
- 移除专业态度的默认选中与“核心演示”推荐标记，避免下一轮试玩被界面暗示；
- 运行生产构建、8 项自动测试、ESLint 与 Git 差异格式检查。

## 观察结果

| 态度 | 压力 | 信任 | 成交意愿 | 控制感 | 阶段 | Storylet 与推进 |
|---|---:|---:|---:|---:|---|---|
| 温和 | 48 | 66 | 69 | 49 | 放松 | 未触发承认；保留原说法，返回行动重试 |
| 专业 | 54 | 61 | 66 | 42 | 谨慎 | 触发 `partial-restoration-admission`；稳定推进交易 |
| 强硬 | 61 | 48 | 60 | 36 | 受压 | 触发 `defensive-restoration-admission`；带关系与离场风险推进 |

- 相同输入重复结算结果一致，输入对象与案件初始状态未被修改；
- Storylet 未命中时也会输出逐条条件结果，右侧调试栏可直接查看原因；
- 三种态度不再由 UI 特判决定是否结算，玩家界面只读取规则结果。
- 站点源码已生成部署提交 `1be3e88`，构建包已生成；Sites 连接器连续返回不可用，因此线上第 8 版尚未更新，本项只标记为“已准备、未发布”。

## 对决定或假设的影响

- 已降低“专业是唯一真正实现的按钮”这一实现风险；
- 三态度现在具备可试玩的策略差异，但当前参数仍只是工作样例；
- 下一项最高价值工作应是外部试玩，而不是继续增加功能或美术。

## 结论的局限

- 尚未由 3—5 名外部体验者验证理解度与选择分布；
- Storylet 条件仅覆盖当前一条证据与一组初始状态；
- 尚未证明三种态度不存在支配策略。

## 下一步

进行 3—5 人试玩，记录首次选择、理由、回应理解、是否重试和主要困惑，再决定调整参数还是增加第二条证据。
