# EXP-010: 规则对齐答复与高保真教师演示需求

日期：2026-07-31

## 测试了什么

确认用户对 CH-002 中结算、议价资源、披露方式与风险转移层级的最终方向，并记录指导老师对下一版展示质量的新要求。

## 方法

- 用户直接填写 `近期开发对齐/05-请你填写的近期决策.md`；
- 对照 DEC-003、DEC-004、DEC-007、HYP-003 与 CH-002，区分已批准方向和仍需实验的精确参数；
- 将“高保真界面”视为同一首案规则的独立展示版本，不覆盖低保真原型和数值实验台。

## 观察结果

- 用户不接受继续使用 0—100 客观总分，提出 `D / C / B / A / S / SS / SSS` 等级制；
- 综合等级由物品客观品质/价值、实际净收益、议价表现和判断质量共同影响；
- 物品品质提供综合等级上限：低价值赝品即使其他表现很好，工作上限约为 C；具体阈值交由后续平衡；
- 用户接受调查行动点与议价容量分离，并要求调试阶段显示精确值；
- 用户希望第一版议价容量参数较宽松，优先展示多轮演绎与回应；
- 用户接受移除“完整说明事实 / 只强调部分信息”抽象按钮，改用选择具体证据实现披露；
- 用户没有修正风险转移的默认定位，因此继续作为部分 NPC、部分案件中的特殊措施；
- 指导老师希望看到一版整洁、接近真实产品的用户界面，而不是只看测试用低保真原型；
- 新高保真 HTML 应与现有两个 HTML 并存，放在同一 `prototype/public/` 文件夹中。

## 对决定或假设的影响

- DEC-003：确认独立议价容量与精确调试显示；
- DEC-004：取消第一版 0—100 总分，采用分项结果与等级制方向；
- DEC-007：移除抽象披露方式，改为具体证据选择；
- HYP-003：第一版采用较宽松容量作为工作假设，仍需用试玩验证；
- CH-002：四个冲突方向均已获得解决，可以关闭；
- 下一项可验证工作转为高保真首案 UI 的设计、实现与真实浏览器任务流审查。

## 结论的局限

- `D—SSS` 的确切阈值、各项权重和品质上限尚未平衡；
- 独立议价容量的起始值、人物修正与每轮消耗尚未通过示例确认；
- 高保真 UI 的视觉方向尚需用户批准；
- 本记录只确认方向，不代表代码和 HTML 已经完成。

## 下一步

先批准高保真 UI 的视觉与信息架构，再用测试先行方式更新规则镜像、制作独立 HTML，并在桌面和 `390 × 844` 手机视口完成真实任务流验证。
