# 玩家知识工作台微循环三分支 v0

Status: Historical failure evidence / Disposable prototype files deleted by user request / Prior Routine verification retained only as historical result

日期：2026-08-21

## 本轮要回答的问题

在不改变作者真相、G2 语义、玩家行动和信息权限的前提下，哪一种低保真组织方式更容易让玩家理解：

1. 新证据改变了什么；
2. 当前仍缺什么；
3. 自己为什么选择下一步或选择收手。

本轮不选择最终 UI，不测试趣味，也不批准概率形式、最强提示、正式产品代码或真人测试合同。

## 冻结输入

三个分支共同使用[具体一局 v0.1](2026-08-21-first-ceramic-concrete-session-v0-1.md)的同一段 G2 软转折：

- 晚 18 世纪外销瓷与显著重组已经形成 G2；
- 候选事故／修复记录开始产生意义，但尚未确认属于现器；
- 玩家可以核对档案归属、转向纯物证调查，或接受 G2 收手。

玩家责任采用 [DEC-025](../../decisions/DEC-025-v3-player-workbench-snapshots-focus-and-final-judgment.md)：系统整理事实、解释、开放问题和调查方向；玩家可选地保存“当前倾向＋首要疑点”，首要疑点只重排注意力；中途快照不产生后果，收手时才必须确认最终快照。

## 原型交付

该原型曾是无依赖的静态 HTML／CSS／JavaScript，并与正式产品路径隔离。用户在否决其核心交互方向后，于 2026-08-22 明确要求删除；`prototypes/player-knowledge-workbench-microcycle-v0/` 的五个未提交文件已经移除，不能再作为可运行原型入口。本记录只保留当时的设计目的、验证结果与失败结论。

原型当时的三个分支读取同一个 `SHARED` 内容对象：

| 分支 | 只改变什么 | 默认表达 |
|---|---|---|
| 鉴定更新流 | 时间组织 | 新事实 → 改变了什么 → 仍缺什么，之后进入玩家快照与行动 |
| 三域鉴定台 | 空间组织 | 已见事实／当前解释／开放问题与方向三个稳定责任区 |
| 文字摘要＋按需关系图 | 展开深度 | 先给文字摘要和开放问题，玩家主动展开已知关系与完整底稿 |

所有分支都能访问同一组 3 条事实、2 条系统解释、3 个开放问题和 3 个行动。低默认展开不等于隐藏权限；摘要分支的完整事实与解释仍可按需展开。

## 状态覆盖

原型可演示：

- G2 刚成立且没有中途快照；
- 选择系统解释、暂不判断或保留异议；
- 首要疑点只重排事实／问题／调查方向，不移除内容；
- 新信息支持、重复或冲突当前解释；
- 保存新快照时保留旧快照；
- 完全没有快照也能继续调查；
- 玩家主动逐级请求提示，最强提示边界保持待确认；
- 接受 G2 收手时必须确认最终快照，暂不判断仍是合法最终判断。

### 真实浏览器交互

使用本机 Chrome 的 Playwright 驱动，在 `390 × 844` 视口逐条执行，结果 `15 checks / 15 pass / 0 console errors`：

- 三分支的事实／解释／问题 ID 集合逐项一致；
- 三分支的行动 ID 集合逐项一致；
- 无快照继续调查、系统解释快照、异议快照、快照历史、焦点重排均可操作；
- 支持、重复、冲突三种更新按合同显示，冲突不会让 G2 自动坍塌；
- 提示可以逐级展开到“最强边界待确认”；
- 缺少最终快照时无法完成收手，但选择“暂不判断＋首要疑点”后可以收手；
- 收手不会自动补造中途快照。

另在 `430 × 900` 窄屏完整渲染三域鉴定台与“摘要＋展开关系图”：未观察到控件重叠、文字截断或关系图越界。页面明显较长，三域分支在窄屏堆叠后信息密度较高；右侧 `STATE DEMO` 在窄屏落到底部。这些是比较夹具的已知形态，不构成最终移动端布局 Pass。

## 这份证据能证明什么

历史上曾实现并以 Routine 方式验证：三个分支可以使用同一内容与权限走完规定微循环，快照、焦点和提示不构成调查门禁，交互脚本没有运行错误。由于原型文件已经删除，该结果只解释当时为什么能进入用户比较，不表示当前仓库仍有可运行版本。

尚未验证：

- 玩家能否区分事实、系统解释和自己的判断；
- 哪个分支最容易理解或最适合手机；
- 玩家是否觉得系统在帮助整理而不是替自己解题；
- 粗概率采用哪种表达；
- 最强提示应止于问题、行动类别还是单项行动；
- 真人测试通过线、趣味、整局节奏、正式视觉和产品实现。

## 下一检查点

本节原计划是由用户三选一或批准组合。用户实际查看后明确否决三个分支共同采用的文字／面板／TODO 式核心交互：它们无法让玩家直观看见自己走过的路径、证据指向、未知区域和自然探索前沿。Routine Pass 继续只证明线路可运行，不能抵消该体验结论。

因此本记录已经结束为一次失败方向证据，不再承担三选一输入。当前检查点改为：先选择 UI／UX Skills，再逐项讨论从黑暗／混沌逐步显影的玩家知识地图；在语义对齐前不制作新版界面，也不进入真人测试。
