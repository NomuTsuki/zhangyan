> 后续：用户明确批准执行建议，修订已接入 `11ea710e`。见[实现与验证](validation/workbench-hifi-v0/VERIFICATION-FRONTIER-CONTINUITY-2026-09-13.md)。以下审查针对原 `370fc2c1`，失败结果与证据保留，不改写成通过。

审查结论：**FAIL — 旧前沿的去向没有统一建模，来源报告专项修复不能代表整图连续性通过。**

最昂贵的缺陷类别是呈现语义与状态转换脱节。程序能判断疑问是否继续生成，却不总能说明它由哪个节点、哪组依据或哪个新问题接替。

## Findings

### F1：没有明确接续道路时，旧虚线按零延迟退场

- **Class:** spec-drift / semantics
- **Evidence:** [map-motion.mjs:33](validation/workbench-hifi-v0/src/map-motion.mjs#L33) 仅用 `canonicalRouteId` 寻找接续道路；找不到时 `Math.max(0, ...[])` 得到 0。[MapView.tsx:75](validation/workbench-hifi-v0/src/MapView.tsx#L75) 在该时点开始 160ms 淡出，问句同样处理。融合 [graph.mjs:223](validation/workbench-map-fusion-v0/graph.mjs#L223) 把不再生成的前沿统一登记为 `resolvedFrontierIds`，没有区分补齐、转向和保留边界。模型 22 种零延迟变体及浏览器 9 组反例支持这一缺陷。
- **Blast radius:** 材料、外观、紫外、工艺、历史、结构变化，以及部分档案顺序。简单延长淡出只能延迟丢失，不能补出关系去向。
- **Recommended owner:** Agent 可统一呈现层的转换接口与时序；具体接续含义须依据既有规则，不能用新证明关系填平空缺。

### F2：已有后续材料提示的前沿，仍使用与目标无关的向下短线

- **Class:** spec-drift
- **Evidence:** 融合 [graph.mjs:28](validation/workbench-map-fusion-v0/graph.mjs#L28) 已声明材料双向的 `continuation.nodeIds`；高保真 [map-layout.mjs:225](validation/workbench-hifi-v0/src/map-layout.mjs#L225) 主要读取 `edgeIds`。没有匹配道路就进入 [openGeometry:166](validation/workbench-hifi-v0/src/map-layout.mjs#L166)，按 ID 哈希选择左右 65px，统一向下 86px。层序 `(907.5,1950)` 等待的基底节点在 `(922.5,1755)`，旧线却伸到 `(842.5,2036)`；从线段起点到目标的距离约 207px，末端约 292px。
- **Blast radius:** “已有后续目标”与“允许保留的开放边界”使用同一回退画法，固定地图位置没有真正约束前沿方向。
- **Recommended owner:** Agent 可按实际接续目标设计固定路径并复用其短段；不可只读取所有 `nodeIds` 并自动生成证明线，因为该字段目前仅是下一调查提示。

### F3：档案专项修复遗漏了先原记录、后核验、尚无整器观察的顺序

- **Class:** spec-drift / test
- **Evidence:** 旧疑问绑定 `archive:t2/3:object`；此顺序下新增的是 `source:obs.archive.*`。主档案道路要在记录与整器观察同时存在时才生成，两者 ID 因而匹配不到。独立模型复现事故／后期 × 归属／实物印证四种组合均 `retireAt=0`；真实浏览器复现事故归属一组。新来源实线有 1800ms 生长，原归属虚线却在开头退掉。
- **Blast radius:** “报告先到→记录后到”的通过不能推广成档案所有顺序通过；后来的整器观察与报告收纳还会增加转换阶段。
- **Recommended owner:** Agent 可补齐从原归属／印证问题到实际报告、来源和主道路的转换。保留归属与实物印证分别成立，不改取得顺序。

### F4：若只把消失的虚线改为实线，会引入错误推理

- **Class:** semantics
- **Evidence:** atlas [graph.mjs:192](validation/workbench-map-atlas-v0/graph.mjs#L192) 至 199、245 至 263 明确包含不同性质的条件。材料两项彼此不能替代；紫外的下一方法是试窗，退出条件却是区域范围已解决；工艺问题可因替代身份路线成立而退出；外观修补大问题在任一探索分支取得后就退出；历史问题需三阶段的共同条件。独立审查与真实会话均确认这些差异。
- **Blast radius:** 直接连材料会暗示相互证明；将阴性记录接成支持会暗示“未检出=不存在”；历史直接连单个新报告会暗示单项证明；把大问题退场标成已解决会夸大调查所得。
- **Recommended owner:** Agent 应先逐项映射既有含义。新增互补材料的静态表现、广义问题的转向表现属于呈现设计建议，标 `review required`；不默认改成绿色证明箭头，也不恢复全部已被用户否定的参照线。

### F5：镜头对旧前沿的保留只为档案来源问题做了特例

- **Class:** spec-drift
- **Evidence:** [MapView.tsx:173](validation/workbench-hifi-v0/src/MapView.tsx#L173) 先以真实图边取邻居，再以 `question:archive:t[23]:source` 单独加入退场问句。材料两节点没有图边，不能由该邻居机制可靠带入；其他非来源旧前沿也不受该特例保护。
- **Blast radius:** 即使修好退场时间，拉回取景仍可能漏掉旧起点或旧问题，玩家看不到接续发生在哪里。当前材料例子同屏能看见两节点，不等于泛化取景机制已具备。
- **Recommended owner:** Agent 可让取景直接使用统一转换描述中的旧锚点、旧问句、接续节点与相关道路，不再按某个问题名字特判。

### F6：已有测试能全部通过，但不能证明整图前沿连续性

- **Class:** test / claim
- **Evidence:** 独立审查者实际运行当前 `check-report-source.mjs` 6/6、`check-reveal-lifecycle.mjs` 5/5，通过结果与上述反例同时存在。来源检查 [27–28 行](validation/workbench-hifi-v0/scripts/check-report-source.mjs#L27) 对反向顺序只比较最终曲线，未检查旧前沿退场；显露检查 [11–15 行](validation/workbench-hifi-v0/scripts/check-reveal-lifecycle.mjs#L11) 为固定五项。固定布局旧检查的紫外“开放边界”断言是在保护无虚假支持，不能为了新检查通过就删掉。
- **Blast radius:** 规则一致、最终布局一致、特定分支动画通过，都可能掩盖中间过程的断裂。之前全绿不是用户感受有误的证据。
- **Recommended owner:** Agent 增加按“前沿来源→后续去向→退场时点”分类的真实状态转换覆盖；保留原结果和本次失败，不放宽基线。新增检查 `review required`。

### F7：来源专项完成记录需要加上当前反例边界

- **Class:** claim
- **Evidence:** 上一轮报告与 CURRENT-STATE 正确保存了特定路径的通过，但不能据此将当前排程继续视为仅等待体验确认。本轮已经发现可重复的功能表现缺陷，且受检页面 SHA 与上轮一致。
- **Blast radius:** 若仅保存成功示范，后续重入会继续把来源修补当作整图完成，再次进行局部补丁。
- **Recommended owner:** Agent 可在原报告加后续反例引用，并更新当前状态和下一步；保留历史通过证据，不改写旧结果。

## 全部前沿家族的接续语义清单

以下是对当前代码的归纳，不是新增游戏规则或已批准的视觉方案。

| 前沿家族 | 当前退场／变化依据 | 修正应遵守的含义 |
|---|---|---|
| 事故／后期 `source` | 原记录出现 | 已有报告找到原始来源；中性对应与可回查保留 |
| 事故／后期 `attribution` | 对象归属成立 | 核对记录是否指向本碗；不能同时宣布事件获印证 |
| 事故／后期 `corroboration` | 实物对应成立，或被待归属的比较报告接管 | 区分已印证与“报告已得、解释仍待归属”，后者不是完成 |
| 事故／后期 `record` | 内部一致成立／争议变化 | 不等于归属或实物对应；本次正常路线未生成冲突变体 |
| `photo-object` | 旧照对象核验 | 真实对应道路；当前针对路径有原路接通机制 |
| `surface` | 试窗后的区域综合 | 真实点位到范围关系；当前针对路径有原路接通机制 |
| `material-base`／`material-sequence` | 另一类材料读数取得 | 互补信息到齐；两者没有单独相互证明关系 |
| `negative` | 当前代码随区域范围成立退掉 | 未检出的检测能力限制继续存在；试窗只是另一种调查 |
| `craft` | 真品比对，或另一身份路线成立 | 要区分走向比对与经替代路线形成判断 |
| `visible-intervention` | 纹饰、成像、事故记录任一取得 | 大问题展开为具体方向；不意味着所有修补问题已解决 |
| `appearance` | 试窗或范围材料出现 | 进入层次／范围调查；与重大结构重组不同 |
| `change` | 照片比较报告取得 | 比较材料与历史适用条件分别表达；不将当前影像独自当历史证明 |
| `history` | 三阶段共同条件成立 | 汇入真实历史解释；不能连一个新记录就宣布历史完整 |
| 8 个 `registered` 未知家族 | 求解器未知登记变化 | 具体配方、非关键区域等可持续保留；不在 G3 统一清空 |
| `conflict` 动态家族 | 真实冲突状态变化 | 保留争议与适用边界，不能作“待补的正确答案” |
| 旧 `context` | 融合本地投影已主动删除 | 旧共享问号不是本轮待恢复内容；NEXT 元数据仍有遗留 |

正常路线的 16 个 ID 已运行覆盖；内部记录争议、8 个登记未知与动态冲突进行了代码路径核查，本轮没有伪造会话状态来声称其浏览器测试通过。

## 主修正建议（未实现）

为每类前沿明确三件事：**它从哪些已有内容产生；下一次相关调查会接到哪里；接续后地图应留下什么。**布局、动画与取景必须共用这些信息。

有真实关系的前沿，从一开始就是该固定道路的一段，新材料到达后沿原曲线完成接通，再退问句。缺少另一份互补材料的前沿，要朝该材料所在方向展开；材料到齐后保留可辨认的互补联系或共同汇入关系，不能伪装成“材料甲证明材料乙”。问题进一步展开时，旧前沿应连续交给实际的新调查方向；能力限制和开放未知则保留适当边界。

不能直接把所有 `nodeIds` 当成答案，也不能把所有 `resolvedFrontierIds` 当成判断完成。先在高保真呈现层逐项明确对应，再复用固定路径与已有动效；复验同时检查正反顺序、替代路径、缺少端点、问题改述，以及旧前沿仍在镜头内。冻结规则、绿色支持线与共同条件语义不变。
