# 知识地图可玩切片 v0 — 第一器物

Status: Validation-only / 可整体丢弃 / 不是产品代码

**双击 `slice.html` 就能玩,不需要本地服务、不联网、不装任何东西。**

这是 V3 第一个**能动手玩**的东西。此前 V3 全是文档与静态走查;这一份把已批准的语义
接到**真的规则核**上,让人可以自由乱点,然后看地图怎么显影。

## 这份切片是什么

| 文件 | 作用 |
|---|---|
| `slice.html` | **构建产物**,可双击。150 KB,单文件,零外部依赖 |
| `case.mjs` | 本案玩家侧投影层:结局表、费用档位、可用性、玩家读数 |
| `harness.mjs` | 无界面自检,15 项。**先验通它再写 UI** |
| `harness-out.txt` | 自检输出 |
| `build.mjs` | 把冻结源内联成单文件,并记录 SHA-256 |
| `template.html` | UI 模板(构建输入) |
| `probe.mjs` / `probe-out.txt` | 前置可行性探针:确认冻结求解器能被自由探索驱动 |

重建:在本目录 `node build.mjs`。自检:`node harness.mjs`。

## 规则不是这里写的

结算全部来自 **已冻结的作者求解器**
`../first-ceramic-author-scenarios-v0/{solver.mjs,fixtures.mjs}` —— 那组文件通过 40 项
契约测试、比对独立编写的黄金预言机、由 DEC-024 批准为作者规格。本切片**只读**它,
一个字节都没改(`build.mjs` 记录其 SHA-256 并写进产物页脚可见的构建戳)。

所以下面这些不是界面演的,是规则核真的在算:

- **早拿后懂。** X 射线先做,读数先挂起;补上对象连续性核对后自动激活,而且不重复计权。
- **重复不计权。** 换一批语料复核会花钱花机会,但不推进阶段、不改可信度(DEC-030)。
- **阴性的能力门。** 紫外筛查没看见补绘,只证明「这次没看见」,不能推出「不存在」。
- **G2 的两条 OR 路线。** 档案六步与物证六步都到 G2,走法完全不同。
- **手动停手。** 阶段冻结在玩家选择的那一刻,系统不自动结束。

## 结局表怎么定的(不是自拟的)

冻结目录里一个动作常对应多个「结局」事件。本案该给哪一个,只用两条推导规则:
以完整 G3 场景用到的事件为本案正典;正典未覆盖的分歧,按其它冻结场景的可达性推,
**不得让任何已声明可达的路线因本表而走不通**。两处需要解释的:

- **X 射线给 `xrayEarly`,不给 `physicalMajor`。** 前者带延迟上下文机制,同时覆盖
  「早拿」与「后拿」两种时机;后者直接给结构事实,反而抹掉「早拿后懂」。
- **T2 归属直接建立,不给 contested。** 本想设计成「没有独立锚点就先给争议」,但冻结场景
  `g2-documented-stop` 的六步路线没有对象连续性核对却建立了归属并被声明为 G2。
  按第二条规则不能让它走不通。**代价:走查里那个「争议 T2」的一局在本案正典下走不出来。**
  它演示的机制是真的(来自 `archive-attribution-contested-not-promoted` 场景),
  但不是这只碗的正典结局。`case.mjs` 里就地写明,没有静默留着。

## 刻意没有做的三件事

1. **不显示 `supports` / `marginals`。** 夹具 `manifest.json` 声明它们是
   *fixture-only technical values*,只为触发通过／拒绝分支存在,**不得**当成似然或产品概率。
   把 `0.9427` 摆给玩家看会同时违反这条边界和 DEC-028 推迟粗概率的决定。
2. **不做「当前最优调查」排序。** DEC-026 授权了这个能力,但排序需要期望决策价值,
   而 DEC-018 没有批准任何相关数值。编一个排序就是**拿假数值冒充玩法**。
   本切片因此只提供路口与前沿(结构信息),不提供推荐(价值信息)。
3. **不做报价、市场与双轨结算。** 本切片只验「调查 → 显影 → 手动停手」这一段。

## 路口层:DEC-031 的落点

[DEC-031](../../../../decisions/DEC-031-v3-exploration-rhythm-is-player-chosen-dead-ends-and-degree-are-the-lever.md)
定的是:设计目标既不是跳跃式探索也不是连锁式顺序探索,而是玩家**自发地在该连续时连续、
该跳跃时跳跃**;真正让人换地方的不是系统推荐,而是**玩家自己撞到的墙**。

界面上的三条对应实现:

- **站位**(刚查完的那个地点画同心环)与**通出去的路**(虚线弧)。可用页面顶部按钮**开关**,
  因为它按 DEC-031 只是呈现,必须能被单独评估。
- **路口只画就近的 4 条路。** 一个路口应该有几条路,不是九条。取舍标准是**地图上的距离,
  纯几何**,不是价值排序;被略掉的动作在下方行动区**一条不少**,面板也明写还有几个。
  这样既满足「醒目度不进入任何计算」(DEC-029／031),也不用假排序冒充推荐。
- **没有路通出去时,就明说没有路。** 这是死路的正面职责。

**注意:真正的度数控制是拓扑设计的事,DEC-031 已登记为杠杆并明确暂不调整。**
本切片没有改动第一器物的既有拓扑,路口的疏密完全是既有拓扑的结果。

## 数值

`slice.investigationBudget = 12` 与 `slice.actionCostTiers = 免费／低／中／高`
都是 `experimental-default`,登记在 [`PARAMS.md`](../../../../PARAMS.md)。
费用是**定性档位不是货币** —— DEC-018 没批准任何单项费用,而 DEC-030 要求费用可见,
定性档位同时满足两条而不伪造一个看起来经过平衡的数字。
预算 12 是按路线长度反推的:两条 G2 路线各 6 步,完整 G3 需 17 步,
所以 G2 从容可达、G3 一局内不可达 —— 这正是 DEC-027 对首案的要求。

> **2026-08-31 更正(上面最后半句是错的,原文保留备查):**
> DEC-027 **从未**要求 G3 一局内不可达。核对原文:其流程图把 G3 画成首案的正常去向之一
> (「多组关系闭合 → G3」),第 41 行原话是「G3 只在所需关系真正汇合时形成」;
> 它真正管的是 G2 一旦靠充分证据建立、后段不许再用决定性证据永久撤销。
> 12 点拿不到 G3 纯粹是预算副作用,不是设计要求。
> 另外「完整 G3 需 17 步」指的是冻结场景里那条具体路线的长度,**不是最短路线** ——
> 最短 G3 路线实测为 **16 步**(`workbench-map-v0/min-g3.mjs`,是上界不是精确值)。
> 详见 [`PARAMS.md`](../../../../PARAMS.md) 的更正条目。

## 已验证 / 未验证

**机器已验(`harness-out.txt`,15 项全过 + 浏览器实跑):** 空局可解且每个不可用动作都
带人话理由;两条 G2 路线各 6 步达成且互不冒充;X 射线先行时挂起并在补上上下文后激活;
重复被判为重复且不推进阶段;紫外阴性停在未过能力门;跨时点对照在没有第二时点时被
一句人话挡住而不是甩一个 fact id;停手冻结阶段且 `systemAutoEnded === false`;
12 次预算真的会用完且 G3 到不了。浏览器里另跑了一局含重复与阴性的脏局,仍到 G2,
足迹计数正确(6 推进 / 1 重复 / 1 阴性)。

**机器不能验,只能真人验:** 好不好玩;地图看不看得懂;"该连续时连续、该跳跃时跳跃"
是否真的发生;死路是读成「换个方向」还是读成「系统惩罚」;12 次机会是否合适;
定性费用档是否被误读为货币;路口层开着还是关着更好。见 `PLAYTEST.md`。

## 边界

- 与正式产品代码完全隔离,**允许整体丢弃**;不导入 `prototype/**`,不被任何产品模块导入。
- 冻结求解器自称「只是验证参考实现,不获得未来生产架构权威」。
  本切片用它当大脑是合法的(切片本身就是可丢弃的验证物),但**不构成**批准它成为产品架构。
- 一处与走查的偏离:档案地点(T1／T2／T3)从第 0 步就可用,而 `player-session.html`
  把它们画成需要先被发现的迷雾。冻结事件确实没给这些动作设前置,所以按规则核如实呈现。
  这更像现实——古董商知道档案存在——但它是**规则核的事实,不是本切片的设计选择**。
