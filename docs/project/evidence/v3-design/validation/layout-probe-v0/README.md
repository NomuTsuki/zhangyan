# “已知与推理”力导向布局对照 v0

Status: **Experimental / validation only**

这不是新产品界面，也不是对地图语义的新决定。它只回答一个问题：

> 不把玩家的探索重写成分类题或时间轴，只调整同一张力导向图的节点分布，能否让局部逻辑更容易被看见？

## 打开

双击 `prototype.html`。页面是单文件、离线、电脑浏览器尺寸；默认打开完整内容的“逻辑岛”候选。

页面可以切换：

- 同一局的少量内容（6 条情报）、关系成形（12 条）和完整内容（22 条）三个快照；
- 当前力导向与候选逻辑岛力导向；
- 点击任意节点，只看与它直接相连的关系。

快照按钮只用于比较同一张图怎样长大，不是界面里的进度条，也不参与候选坐标。

## 数据与关系没有换

快照由当前 `workbench-map-v0/session.mjs` 与 `projection.mjs` 实算，不手写节点或关系。22 个行动全部通过 `take()`，任何一步被规则拒绝都会让构建直接失败。

| 快照 | 情报 | Finding | 已查实结论 | 关系 |
|---|---:|---:|---:|---:|
| 少量内容 | 6 | 2 | 1 | 14 |
| 关系成形 | 12 | 2 | 2 | 21 |
| 完整内容 | 22 | 4 | 4 | 43 |

满局仍保留四类既有关系：

- `latent`：几条情报指向同一底层问题；
- `prereq`：先有前者，后者才拿得到；
- `caught`：后来得到前者，才让既有后者有意义；
- `supports`：情报支撑已查实结论。

两种布局消费完全相同的节点、文字和边。`supports` 在未选中节点时仍然收淡，点击相关情报或结论后逐条展开。

## 两种空间原语

### 当前力导向

逐步复现 `workbench-map-v0/template.html` 的现有布局原语：所有关系使用同一种弹簧、所有节点互相排斥，只有已经查实的结论在首次落位后钉住。其余节点在后续每一步都可以整体移动。

### 候选：逻辑岛式受约束力导向

候选仍是一张自由生长的点图，没有问题泳道、推理列、取得顺序列或 G 阶段分区，也不预留未知节点。

它只改变布局物理：

1. `latent`、`prereq`、`caught` 是结构边，以不同的实验弹簧长度和强度组织局部簇；
2. `supports` 全部保留，但不合并逻辑岛；它的引力弱于任何结构边，并按目标结论的支持边数量归一化，避免 23 条扇形边把全图吸成一团；
3. 节点圆点、完整文字标签和标签留白共同进入矩形碰撞，而不是只让圆点互相避让；
4. 最大结构岛获得无语义的画布中心目标，其余结构岛按稳定 ID 哈希分散到外圈椭圆；这只是 component packing，不代表分类、路线或先后；
5. 每得到新内容，只提高新节点、新增结构边端点及其两跳邻域的可动性；其他旧节点由上一坐标软锚定；
6. 旧结论使用更强的稳定约束，但仍可在避碰时移动。普通节点不按出现年龄硬钉；
7. 图没有变化时不重复求解，因此相同终态再次布局为零漂移。

候选数据与坐标函数都不再携带或读取 `lane`、`laneOrder`、`acquiredAt`、`conclusionOrder` 或 `stage`。取得顺序只用于构建三个合法快照，不会变成节点的空间地址。

## Experimental 参数边界

弹簧长度、弹簧强度、软锚、岛位重力、碰撞留白和每步迭代数都只存在于本 validation probe 的 `layout.mjs`。它们不是产品数值，没有写入 `PARAMS.md`，也没有被批准为正式默认值。

## 构建与检查

在本目录运行：

```text
node build.mjs
node check.mjs
```

文件职责：

- `probe-data.mjs`：用现有规则合法重放同一局；
- `layout.mjs`：当前力导向复现与候选增量逻辑岛布局；
- `template.html`：只让两种坐标共用同一个点、文字和直线关系 renderer；
- `build.mjs`：只读生成三个快照、记录八个来源文件 SHA-256，输出 `prototype.html`；
- `check.mjs`：检查图规模、四类关系、标签碰撞盒、逻辑岛成员、禁用字段、数组重排确定性、终态零漂移、跨快照位移和 caught 桥接；
- `prototype.html`：生成物，不手改。

当前机器检查覆盖：

- 6 / 12 / 22 三个快照的节点和关系规模；
- `supports` 不参与结构连通，且其引力按结论度数归一化；
- 标签碰撞盒不压叠、不越界；
- 节点或边数组倒序不改变候选坐标；
- 图未变化时重复终态布局零漂移；
- `WHOLE → BASE → OBJECT_CONTINUITY` 经 `caught` 接住 `XRAY` 后，结构桥两跳邻域可以重排，无关孤点不被误纳入。

## 这轮怎样判断

机器检查不能证明地图更容易理解。真人比较时只看四件事：

1. 第一眼能否分出主簇、小簇与暂未接上的点；
2. 能否指出当前已经站得住的判断，并找回至少两条依据；
3. 能否认出一条后来接住旧证据的桥，而不把图读成固定步骤；
4. 从前一快照切到后一快照时，能否说出局部哪里改变，同时仍认得原来的结构。

若候选仍被读成任务路线，或新内容一出现便让整张图失去方位，本方向失败，即使机器检查全绿也不能采用。

## 不在范围内

- 不改作者求解器与冻结夹具；
- 不改行动可用性、步数、费用、证据、文字或结论语义；
- 不裁决 Finding 的机械价值、G1/G2/G3 或地点层；
- 不替换当前 `workbench-map-v0/prototype.html`；
- 不证明正式视觉方向、趣味或零背景玩家通过。
