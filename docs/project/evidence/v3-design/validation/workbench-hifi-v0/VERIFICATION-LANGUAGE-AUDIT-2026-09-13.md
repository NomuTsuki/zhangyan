# 英文漏译修复与调查换序核验

用户反馈原话：“我玩的时候出bug了。英文的界面出现了中文。除了这个地方，你再仔细核验一下其他地方。”[原始截图](../../../../../portfolio/2026-09-13-language-order-fix/2026-09-13-user-language-leak.png)已保存；截图证明出现漏译，没有提供唯一的完整调查顺序。

## 问题与修正

真实最小复现只需一步：新局进入英文，选择 `Later treatment → Attribute the later records`，先取得后期记录归属报告。尚未取得原始记录时，地图和右栏出现“这份关系核验所指的原始记录是什么？”；点击后解释也仍为中文。修复前在实际浏览器和真实会话派生检查中均复现。

这是条件分支的翻译目录缺项。之前的常用路线先找原记录再核验，没走到报告先到的分支；语言偏好本身没有回退。扩大检查还发现照片先于底足观察、层序先于基底材料、事件已印证但归属未核实、共同身份条件等分支遗漏。`src/locales/en-case.mjs` 补充10段源文案，覆盖11种匹配形式（其中一段还会经既有“声明→注明”清理生成另一形式）。不更改证据、前置条件或道路语义来消除漏译。

本轮产品修正限定于翻译目录与重新生成的离线页／构建戳；新增两份检查脚本及 package 命令，并保存验证与过程记录。此前收尾、双语实现等未提交修改继续保留。没有新增提交、推送、改动录像、策划案或周报。

### 保留的失败与限制

新增浏览器脚本首次检查道路时，连续点击同一汇流组的不同入路，触发了产品正常的“再次选择即取消”；后改为每次检查前明确清除选择。另一次 `Records` 文本同时匹配顶栏历史与地图上的 `Records–object comparison`；后把定位限定到 `.game-topbar`。两项属于检查操作的问题，产品语义与断言未放宽，失败输出保留。

客户端恢复后的沙箱先拦截浏览器／Vite进程，返回 EPERM；取得命令执行授权后完成构建与浏览器检查。该启动限制与页面漏译分开记录。

实现者查看了真实截图：一步复现中的英文疑问及右栏详情能完整呈现；8次调查中的原漏译也已翻译。全览30%时地图文字很小，仍只用于看结构，未将其宣称为逐字可读。英文措辞自然度、所有可能顺序、其他设备与浏览器、未来新增文案均未取得真人或穷尽验证。
