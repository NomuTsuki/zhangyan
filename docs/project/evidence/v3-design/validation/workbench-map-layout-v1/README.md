# 结论牵引星座布局试玩 v1

Status: **Experimental / pending human verification**

2026-09-04 真人复核：用户认为它只比原布局“略好一点点”，仍未通过，并继续指出 Finding 名实不符、三栏缺少共同聚焦、逻辑方向没有形成自上而下的可读结构、古董内容负担过重。详见 [真人试玩复核](PLAYTEST-RESULT-2026-09-04.md)。这些是问题记录，不是已批准的重构方案。

同日用户批准先做内容骨架、暂不动界面；产物见 [第一器物玩家推理骨架 v0](../../2026-09-04-first-ceramic-player-reasoning-backbone-v0.md)。它仍是待用户复核的 Design Candidate。

这是当前 `workbench-map-v0` 的独立可操作副本，只验证一个问题：把“结论牵引自由星座”放回真实行动循环后，玩家是否更容易看出“我为什么得出这条判断”。它不是新产品版本，也没有替换原工作台。

## 打开

双击本目录的 `prototype.html`。它是单文件离线产物，只做电脑浏览器尺寸，不需要安装或启动服务。

最短比较方式：同时打开本目录和 `../workbench-map-v0/prototype.html`，在两边执行同样的手段。除中间地图的坐标、直线绘制与点击聚焦外，玩法和文字应相同。

## 这份入口只改了什么

- 四类既有关系全部参与同一张自由节点图的坐标求解；没有泳道、时间轴、阶段栏、匿名中转点或全局捆线。
- `supports` 是一等布局约束：目标距离短于另外三类边，超过阈值后另加长尾惩罚；同一情报支撑多个结论时，会自然落在它们之间。
- 交叉、浅角交叉、边穿过其他完整标签、标签互压都会进入局部优化目标；可见标签和碰撞盒共用同一套换行。
- 旧节点采用软锚，新节点及新增关系邻域获得更大移动空间。第一拍飞入动画的临时坐标会在第二拍求解前被过滤，不会把新节点误当旧节点。
- 关系默认画成可直接追踪的直线。点击任一节点，只突出它的直接邻居与关系；再点一次或点空白处恢复全图。
- 画布尺寸改变时会重新求解，而不是沿用旧尺寸的“同图零计算”快路。

## 明确的假设边界

这份独立入口有意用软锚替代原入口的“已成立公理落位后硬钉”。这是本布局探针的 **Experimental 假设**，不修改 DEC-032，也不修改 `workbench-map-v0`。玩法、动作可用性、点数、费用、证据、Finding、公理、G1/G2/G3 和玩家可见文字都沿用当前工作台。

## 参数

全部可调布局数字集中在 `params.mjs`，身份都是 `experimental-default`；登记理由与回滚条件见 `PARAMS.md`。

相对 `layout-probe-v1` 唯一新增的几何默认值是 `labels.roundingSafety: 0 → 0.5px`。原因不是放宽检查：真实中栏更窄，碰撞求解后的坐标又保留两位小数，两个标签可能因不足 `0.01px` 的舍入误差重新接触；这里实际多分开 `0.5px`。曾试把 `collisionPasses` 从 `180 → 360`，对该接触没有作用，因此已回退到 180。

## 构建与检查

在本目录运行：

```text
node build.mjs
node harness.mjs
node check.mjs
```

- `build.mjs` 内联冻结求解器、现有语义/会话/投影和本布局模块，并记录八份源文件 SHA-256。
- `harness.mjs` 是原工作台语义套件，检查行动、投影、决策面、点数与玩家文字没有漂移。
- `check.mjs` 检查 22 步/43 边全量图、四类边全部参与、`supports` 短距与长尾、第一拍 staging 过滤、确定性、完整标签避碰、边界、离线内联和聚焦入口。

## 当前机器边界

机器可以证明规则没有漂移、坐标确定、标签不互压；不能证明地图对玩家更清楚。规范 1400×920 满图仍测得 27 处直线交叉和 10 次边穿过非端点标签，这是已知残余，不把它描述成视觉通过。旧节点在关系大幅增长时也可能明显移动，必须由真人判断“可重认性”是否换来了足够的局部清晰度。

真人短测见 `PLAYTEST.md`。
