# HYP-001: 标准 Web/H5 可能是当前项目的低风险实现路线

Status: Supported

日期：2026-07-22

## 假设内容

对于当前 2D、竖屏、UI 与状态驱动的《掌眼》，标准 Web/H5 技术可能比 Unity 更快形成完整可玩版本；但若最终入口是微信小游戏而非微信内网页，或后续出现重场景、动画与引擎工具需求，Unity/团结路线可能更有优势。

## 为什么重要

引擎选择会影响学习成本、代码语言、资源管线、包体、启动速度、手机适配和发布流程，属于不应凭术语混用直接锁定的系统边界。

## 当前证据

- 当前 Web 原型已验证页面、触控布局、状态流程和在线访问可行；
- Unity 官方支持构建 Web 内容，也提供微信小游戏转换与部署链路；
- 2026-07-31，用户转述指导老师确认目标是通过微信内网址打开的普通 H5，“和公众号链接的网页一样”，不是微信小游戏；
- 团队目前没有游戏或 H5 项目经验。

## 验证方法

先确认最终目标入口，再为候选路线比较：首次可运行时间、同一竖屏交互切片的实现成本、构建包体、冷启动、常用手机兼容、调试体验和发布步骤。若目标仍不清楚，先保留规则核心为与 UI/引擎无关的 TypeScript 数据模型。

## 成功与失败判据

- 成功：标准 Web/H5 在关键设备上满足体验，并以显著更低学习与发布成本完成核心切片；
- 失败：目标平台硬性要求微信小游戏/Unity 工程，或 Web 技术样片在关键性能、资源或工具链需求上不可接受。

## 验证成本

中，说明：澄清入口成本低；完整对比需要安装另一工具链并制作小样，但远低于中途迁移完整项目。

## 结果与影响

目标入口已经澄清，且现有 Web 原型能够覆盖当前二维、竖屏、状态与文字驱动的核心切片。标准 Web/H5 成为当前批准路线，HYP-001 标记为 Supported。

这不等于最终发布已经完成：公开版本仍需验证托管、HTTPS、微信内实机兼容；若后续入口改变或出现 Web 无法满足的明确能力约束，再重新开启路线比较。
