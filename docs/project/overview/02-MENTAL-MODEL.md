# Mental Model

> 这是面向人的简化投影，不是新的项目权威或活动账本。若本摘要与权威项目记录或现场证据冲突，以权威记录和现场证据为准。

最后更新：2026-08-14

## 核心比喻

把器物真相想成一座真实存在的山。山从开局就在那里，不会因为玩家相信什么而变形。

玩家手里拿的是一张会不断补全的地图：检查器物得到事实，事实支持或反驳一些鉴定主张，主张又让不同候选真相变得更可信或更不可信。所谓“下山”只是玩家从混沌走向清楚，不是客观真相从编号 2 变成编号 4。

```mermaid
flowchart LR
    Mountain["山本身<br/>固定真相与价值"] --> Shadow["看见一块地形<br/>原始事实"]
    Shadow --> Claim["这意味着什么<br/>鉴定主张"]
    Claim --> Map["更新地图<br/>候选真相与相信程度"]
    Map --> Choice["下一步查什么<br/>或现在收手"]
```

## 五个方面

这是此前五个开发责任区在 V3 的状态，不是五套孤立引擎：

| 责任区 | 人话解释 | V3 当前状态 |
|---|---|---|
| 1. 物品客观真相 | 山本身：身份、历史、状态、品质与价值 | **当前主线**；先定义完整问题与证据拓扑 |
| 2. 玩家认知 | 玩家怎样根据事实形成、修正并表达判断 | **当前主线**；知识图、后验和温和引导待设计 |
| 3. NPC 认知 | NPC 怎样理解器物与玩家 | 停放，不进入启动批次 |
| 4. NPC 底层画像 | NPC 稳定的能力、目标、风险态度与处境 | 停放 |
| 5. NPC 局内状态与行为 | NPC 此刻怎样回应、隐瞒、议价或离场 | 停放 |

当前只打开前两个责任区，目的是先做出一个完整“识物”游戏，而不是把 NPC 概念继续堆在没有地基的系统上。

## 四张不能混用的图

| 图／账本 | 记录什么 | 玩家是否直接看见 |
|---|---|---|
| 作者真相模型 | 完整历史、身份、状态与真实价值 | 否 |
| 作者证明／依赖图 | 哪些事实和主张怎样支持结论、有哪些替代与恢复路径 | 否 |
| 玩家知识图 | 已发现事实、允许知道的关系、当前判断与开放问题 | 是，但只显示玩家已知部分 |
| 概率与行动层 | 后验、调查价值、成本、风险和继续／停止 | 部分，用自然语言与可展开数字表达 |

Ron Gilbert 的依赖图可以帮助作者检查分叉、汇合、瓶颈和死路，但不能原样复制给玩家。玩家图更像一张属于玩家的案卷：帮助回忆和争辩，不是攻略。

## 一个最小例子

- **事实：** 接缝处观察到一层与表面不同的旧漆；
- **鉴定主张：** 这件器物可能存在旧胎与后期重修层；
- **候选真相：** 现代仿制、旧胎重修、时代完整品的相信程度发生变化；
- **行动：** 检查胎骨或结构证据，验证重修主张；
- **收手：** 如果剩余高价值可能值得继续，就承担成本；如果新增调查的价值已经不抵成本，就带着剩余不确定性做终局选择。

事实一旦可靠观察到就是事实；真正变化的是主张和候选真相的可信度。这样可以保留“扫雷式联动”的全局感，又不把未观察节点伪装成已知。

## 为什么经济终局必须先定

同一条证据可能大幅降低不确定性，却完全不影响玩家最后的选择；也可能只改变一点概率，却决定是否值得承担高额检测或物损风险。只有知道玩家最后要出售、持有、报价还是选择渠道，系统才知道“信息增益”是否真的有用。
