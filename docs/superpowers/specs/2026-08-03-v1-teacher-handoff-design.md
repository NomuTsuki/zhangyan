# 掌眼 V1 教师交付收口设计

日期：2026-08-03

状态：已批准；依据 DEC-010 与用户“请继续”的执行授权

## 目标

把最新评分修正版收束为一个可解释、可验证、可追溯的 V1 教师提交版本，使老师能够：

1. 不安装开发环境，直接打开正式演示；
2. 结合项目说明理解完整游戏内核，而不是只理解一个简单案例；
3. 按演示说明观察证据、信息公开、NPC 重估、有限议价和多维复盘；
4. 清楚区分当前已实现内容、验证证据、工作参数、未验证面与 V2 规划。

## 非目标

- 不启动 V2；
- 不统一数值权威源；
- 不把根工作区 31 个混合文件整包导入；
- 不改变高保真玩家流程、NPC 规则、评分公式或视觉界面；
- 不增加第二案件、长期经济、登录、存档、部署或微信平台能力；
- 不把当前教学案例描述成已经完成玩法平衡。

## 权威边界

### 正式 V1 主体

唯一正式运行主体为：

    掌眼_Codex启动包_v2/掌眼_Codex启动包_v2/prototype/public/掌眼_高保真教师演示.html

它是评分修正版的 canonical 单文件，内联 CSS、JavaScript 与 SVG，可离线运行。

### 历史低保真

掌眼_低保真交互原型.html 与 standalone/client.js 保留为历史和开发调试快照，不代表当前规则权威。它们仍含旧共享行动点、旧 0—100 结算和旧披露语义，不进入教师演示包。

V1 不把根工作区的未提交 standalone 大补丁迁入。该补丁虽含 resolveBuyout，但仍错误消耗调查 AP、缺少议价容量和调查锁定，并保留已废弃结算；迁入会跨越最小修正边界。

### 数值实验台

掌眼_数值实验台.html 是批量模拟和参数研究工具，参数仍是工作假设，不是正式运行时权威，也不进入教师演示包。

## 已知测试失败的设计处理

### 根因

提交 61ef25d 为低保真 HTML/client 增加了 15 条现行规则静态断言，却没有提交对应实现。committed standalone 与生成 HTML 从 4afd29a 后未同步。当前 generate-standalone.mjs 也不能安全重跑：它会把已经移除 reservationPrice 的新案件数据与仍读取该字段的旧客户端拼接，产生 NaN 定价。

### 修正

不伪造函数名，不复制不合格的脏工作区实现，也不取消低保真基础检查。将 standalone 测试改为两层：

1. 历史低保真 smoke：验证自包含、单一内联脚本、脚本语法、源客户端确实嵌入生成 HTML、基础页面与调试入口仍存在；
2. 当前 React 调试面契约：保留 page.tsx 对当前规则入口和信息边界的静态检查。

真正的买断语义继续由 rules.test.mjs 的行为测试保护：接受或拒绝都终局、调查 AP 不变、议价容量消耗 1、结算结果正确。

在削减错误静态期望前，先增加 README 权威边界红灯，证明测试修正没有把低保真重新包装成当前规则。

## 教师文档

仓库增加三个教师入口：

1. 根 README.md：完整项目说明、权威入口、系统模型、技术路线、验证状态、仓库地图和 V1/V2 边界；
2. docs/teacher/00_请先看.txt：最短打开顺序与离线说明；
3. docs/teacher/01_掌眼_V1_项目说明.html：适合老师直接阅读和打印的完整项目说明；
4. docs/teacher/02_掌眼_V1_演示说明.html：10—15 分钟演示路径、观察重点和正常分支说明。

两个 HTML 文档不依赖外网，不读取本机绝对路径，不暴露内部 Agent、恢复目录或开发平台项目 ID。

## 交付物

### 教师演示包

严格白名单、扁平五文件：

    掌眼_V1_教师提交包/
    ├─ 00_请先看.txt
    ├─ 01_掌眼_V1_项目说明.html
    ├─ 02_掌眼_V1_演示说明.html
    ├─ 03_掌眼_V1_教师演示.html
    └─ 04_版本与校验.txt

该包不包含源码、低保真、数值实验台、Agent 配置、项目内存、绝对路径、缓存或内部托管配置。

### 完整源码包

另行从冻结标签使用 git archive 导出完整受跟踪仓库，不读取任何工作区未提交内容，不包含 .git、node_modules、dist、恢复点或根工作区 31 个混合文件。

源码包与教师演示包分开，避免老师把内部研发材料误认成正式演示入口，同时满足提交完整仓库的要求。

## 版本与 Git

- 收口分支：codex/v1-teacher-finalize；
- main 本轮不移动；
- 根工作区不清理、不重置、不合并；
- 冻结标签：v1.0.0-teacher-handoff；
- 标签使用 annotated tag，不使用 final 字样，也不强制移动；
- 标签错误在对外交付前可删除重建；一旦包已交付，只能发布 v1.0.1-teacher-handoff。

提交分三层：

1. 预检、决定、规格与计划；
2. 低保真测试契约和权威说明修正；
3. 教师文档、项目状态和最终验证证据。
