掌眼古玩鉴定 × 信息不对称 × 交易决策

玩家要做的不是猜“真或假”，而是在有限行动与双方有限认知中，把局部线索组织成证据，再把判断写进一笔有代价的交易。

01 · 先看结论

这是一个可运行的玩法切片，不是一张界面效果图

《掌眼》希望把古玩鉴定中的“观察、追问、保留、公开与议价”组织成可复盘的游戏决策。V1 已经能够从来客接待走到最终交易和多维结算；当前教师版本的任务，是说明这套内核如何运作，并展示它已被实现到什么程度。

唯一正式入口 03_掌眼_V1_教师演示.html

自包含、可离线双击打开。低保真原型与数值实验台均不是本包的正式运行主体。

最终载体 普通响应式 Web / H5

目标是通过微信聊天或公众号中的网页链接打开，不是需要 AppID 和提审流程的微信小游戏。

项目优先级 玩法 → 视觉 → 技术 → 文化内容

先让核心循环自洽、可玩、可解释，再逐层增加正式美术、工程能力与文化内容。

V1 的证据边界 证明闭环可运行，不证明长期平衡

一局教学案无法代表多案件、长期经济、不同难度和一般玩家体验已经成立。

验收主体仍是游戏本体。 项目说明与演示说明用于帮助理解，不替代游戏本身；老师提供建议和指导，项目从设计到开发由项目组负责。

02 · 核心体验

从局部证据，走到一笔有代价的决定

游戏不强制“先检测完、再和 NPC 对话”。玩家可以边看器物边询问，用新证据反过来核验陈述；但每一次调查都消耗同一套有限预算，所以“还要看哪里、要不要现在公开、何时停止调查”本身就是玩法。

  1. 接待来客听取卖家陈述、初始开价与公开人物线索。
  2. 交叉调查观察器物、询问、带证据追问或共同检测。
  3. 管理信息证据先归玩家私有，是否公开由玩家决定。
  4. 有限议价把判断写进报价；卖家依据自己的认知与状态回应。
  5. 双层复盘同时看客观得失和当时信息下的判断质量。
证据簿的职责

只读的信息仓库

证据簿负责收纳和复查信息，不在簿内提供询问或交易动作。玩家关闭证据簿后，回到当前页面决定下一步。

态度的职责

修饰行动，不替代行动

“温和求证、专业核验、直接质疑”影响关系与回应方式；真正的问题仍是问了什么、公开了哪条证据、处于怎样的历史和状态。

调查的职责

降低不确定性，但不会免费给答案

证据可能只指向下一步，也可能互相冲突。专项检测还需要 NPC 同意，并同时支付调查行动和价值成本。

交易的职责

让判断承担后果

接受、报价、拒绝都不是脱离调查的独立小游戏；它们把此前证据、卖家认知和风险判断落实为客观结果。

03 · 信息模型

真相、玩家认知、NPC 认知与共享事实彼此分离

系统不会让 NPC 偷看隐藏真相，也不会用“随时说谎”制造不可核验的不确定性。双方都可能信息不足，也都可能选择不说；但被客观证据确认并公开的事实会进入共享层。

信息层它决定什么谁能读取
器物客观真相观察与检测结果、真实价值、局末客观结算。运行规则；局末才向玩家揭示。
玩家私有认知玩家已发现但尚未公开的证据，以及据此形成的后验判断。玩家与判断质量系统。
NPC 私有认知卖家的经历、专业程度、记忆、误判、动机与当前估值。NPC 行为与定价规则。
双方共享信息已公开物证、共同检测结果和可核验的补充口供。玩家与 NPC；双方仍可作不同解释。
允许“真诚但错误”，不允许凭空捏造。 NPC 可以把家族记忆误当作可靠来源，也可以回答“不知道”或拒答；玩家可以只公开对自己有利的证据，但不能生成并不存在的物证。对专业、重真诚的 NPC，明显的选择性披露也可能损伤信任和成交意愿。

这套边界让同一件器物能够形成多条演绎路径：某条路信息增长慢但不教育卖家；另一条路公开关键证据后能快速补足证据链，却也可能让 NPC 重新估价。信息公开因此既是验证手段，也是有代价的交易行为。

04 · 资源、人物与叙事

线性减少的资源，持续变化的证据和 NPC

调查行动 首案 6 点

观察、普通询问、带证据询问与共同检测使用同一调查预算。它只减不增，用来制造调查顺序的机会成本。

议价容量 独立计算

正式报价使用独立容量，由 NPC 人物、演绎结果和当前状态共同决定。一次报价消耗 1 点，NPC 同轮还价不重复收费。

首次正式报价会锁定调查，使流程从探索收束到成交；在此之前可以暂离交易页返回调查。无论调查行动或议价容量是否耗尽，“按当前要价买下”和“拒绝交易”始终可用，因此不会出现无法结束一局的死锁。

NPC 的四个动态状态

压力

表示被逼迫、时间与冲突造成的张力。过高并不等于自动让价，可能触发抵触。

信任

影响卖家是否愿意补充信息、接受解释和承担合作风险。

成交意愿

表示继续谈成这笔交易的动力，与急迫度、外部选择和互动历史有关。

控制感

表示卖家是否仍认为自己掌握谈判节奏，影响让步方式和候选行为。

“纺锤形”回应结构

每轮行动先根据证据、问题、表达方式、人物档案和历史生成多个候选反应，再用硬条件过滤并按状态评分，最后收敛为一个结构化结果和一段可读回复。这样既保留剧情演绎的差异，又避免分支无限发散到无法测试。

05 · 定价与胜负

“买到什么”与“为什么这样决定”必须同时成立

NPC 的最初开价不是物品真值，也不是唯一价格锚点。卖家可能高估赝品，也可能低估珍品；玩家的参考簿同样只读取玩家当前可见信息，提供偏保守的后验参考，而不是系统泄露的正确答案。

客观交易结果

按隐藏真相结算

器物真实价值、成交价格与检测等额外成本共同形成实际净结果；拒绝交易不会凭空获得物品价值。

判断质量

只看当时可见信息

评价玩家是否依据已掌握证据作出合理判断，不读取隐藏真相，因此能区分“幸运蒙对”和“有据判断”。

议价表现

衡量价格执行

参考入场价、实际成交价和当局可达谈判区间，观察玩家是否把已有判断有效转化为交易条件。

综合成果

D — SSS 等级

由物品品质、净收益、议价表现和判断质量共同构成；物品品质提供综合等级的基础区间与上限。

V1 已移除旧的 0—100“客观总分”。 单一分数会把真实价值、压价能力、风险与判断依据混在一起，甚至让任何盈利成交看起来都是满分。现在玩家先看四个可解释分项，再看综合等级。

判断质量内部仍使用决策合理性、后验确定性、证据链稳健度与合成判断四个调试维度。单条强证据不能直接得到最高等级；交叉来源验证或真正决定性的证据，才有资格进入最高档。精确过程只在局末开发复盘中显示，不进入普通玩家界面。

06 · 首案剖面

“民国漆木首饰盒”是一局低级场教学案

卖家刘先生急于出售、看重诚意、经验一般，最初开价 80 点。当前正式演示固定的客观真相是“旧胎重修真品”：木胎为民国晚期旧物，但表面经过现代翻修，锁扣后配、底款后刻，真实价值为 65 点。

80卖家初始要价
65公开证据后重估
50演示中的玩家报价
58本路线 NPC 还价

推荐演示先检查“接口”，得到“现代胶痕”，再在“修复历史”问题中公开该证据。卖家据此将要价从 80 正式重估到 65；玩家报价 50 后，NPC 在本路线中还价 58。若按 58 买下且没有额外检测费，客观净结果为 65 − 58 = +7。

80 → 65 → 58 只是稳定复现因果链的演示路线，不是唯一正确玩法。 观察其他位置、换问题、保留证据、改变表达方式、继续补证或拒绝交易，都会形成不同证据链与状态变化。当前案例故意较简单，也不能说明锚点级证据每局都会出现或被找到。

内容系统为同一器物预留了“现代仿制品、旧胎重修真品、被低估的珍品”三类客观真相，用于测试真相隔离与价值跨度；教师演示只固定其中一类。后续低级场应以稳定判断和缓慢积累为主，中高级场再逐步提高信息风险、额外检测价值和收益方差，不能让新手开局就退化成买彩票。

07 · 视觉与内容表达

插画负责定位，文字负责鉴定事实

器物当前采用非写实二维插画，帮助玩家建立正面、底部、接口、锁扣和内腔等空间位置；胶痕、细纹、刻款、氧化与锁扣结构等微观事实由文字证据准确陈述。这样不会要求玩家从风格化像素中猜一个并未真正画出的细节，也便于规则测试和后续专家校订。

低价值首案暂不制作高成本写实资产。后续精品、珍品可以在结算后加入一张更写实的器物讲解图，用于文化知识和真实特征说明；该方向已经记录，但不属于 V1 已实现内容。

界面边界：中间手机画布是玩家界面。桌面左侧教师说明、右侧可展开开发复盘只用于展示和调试；手机视口会隐藏这些区域，精确 NPC 数值和隐藏真相也只在局末解锁。

08 · 技术与交付

标准 Web 已覆盖当前核心，不需要先进入 Unity

当前实现使用 React、TypeScript、CSS 与内联 SVG，正式教师演示由构建流程生成一个包含全部样式、程序和插画的 HTML 文件。它可以离线双击打开；未来公开版本再部署到 HTTPS 静态地址，通过微信聊天或公众号链接访问。

当前已经选择当前没有选择未来需要再验证
普通响应式 H5、标准浏览器技术、单文件教师演示。 微信小游戏工程、小游戏 AppID 与提审、Unity 或团结引擎迁移。 HTTPS 托管、微信内置浏览器、Safari、真实设备安全区与软键盘。

教师演示包与完整源码包分开交付：前者只保留五个经白名单审定的阅读和运行文件，避免把历史原型或研发资料误当作正式入口；后者从同一个冻结版本导出受跟踪仓库，用于完整保存和审阅。

09 · 完成与验证边界

实现、验证与尚未证明的事情分开陈述

已实现
来客、交叉调查、证据簿、具体证据公开、NPC 正式重估、独立议价容量、交易锁定、买下或拒绝、多维等级复盘，以及桌面教师/开发信息分区。
已技术验证
规则与界面回归、TypeScript 类型检查、代码规范检查、自包含构建，以及桌面与 390 × 844 手机视口的真实 Chrome 核心路径、焦点、触控尺寸、无横向溢出和控制台检查。冻结版本的最终命令结果与文件哈希以“04_版本与校验.txt”为准。
已确认边界
老师能够找到关键入口、理解证据公开并完成交易，这一基本理解由项目负责人确认；它只覆盖当前老师与演示闭环，不能外推成一般目标玩家验证。
尚未验证
具体数值是否平衡、长期是否有趣、多案件信息披露是否自洽、中高级场与厚尾价值体验、一般玩家认知负担、公开 H5 托管和真实微信环境兼容。
已知限制
当前只有一局较简单的低级场教学案；器物插画不是最终正式美术；参考报价、NPC 权重、议价容量、等级阈值和检测成本仍是工作参数。

自动测试的职责是防止已确认行为在改代码时意外退化，例如行动成本、隐藏真相隔离、单条证据封顶、交易不会死锁、自包含文件和玩家/开发信息边界。测试通过说明“实现仍符合当前规则”，不说明“这套规则已经平衡、有趣或得到玩家认可”。

10 · V1 封存之后

V2 先统一权威来源，再扩内容和降低门槛

V1 本轮只做教师交付所需的最小收口，不把结构性重构混进冻结版本。V2 启动时会先核对 V1 冻结版本、现有数值定义与实现边界，再执行已经批准的第一项核心产品工程：统一数值权威源。

  1. 统一数值与规则来源：让生产规则、实验台、单文件和测试通过明确接口读取同一套权威模型，区分生产参数与实验参数。
  2. 建立可调案件与自动模拟：在不同真相、NPC 人物和成本配置中寻找支配策略、死局和异常评分，再安排有代表性的人类试玩。
  3. 扩展多难度案件：低级场强调稳定学习，中级场提高成本与方差，高级场强化人物辨认、熟练检测与风险承担。
  4. 逐步降低认知门槛：在玩法内核完整后，再将提示、推荐、半自动或自动化作为可选择的上层辅助，不让它改写底层真相。
  5. 补充正式内容与发布验证：开展文化与器物知识校订、正式美术、真实设备和微信网页环境验证。
V1 应怎样被评价：请重点看核心循环是否能表达“证据—认知—交易—复盘”的因果关系，玩家与开发信息是否分离，以及项目是否诚实标明未完成部分。请不要把演示路线的顺利成交误解为完整数值平衡已经成立。
