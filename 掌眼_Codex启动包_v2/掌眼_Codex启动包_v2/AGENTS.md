# AGENTS.md — 《掌眼》仓库规则

## 1. 产品约束

- 2D、手机竖屏、古玩鉴定与交易博弈。
- 周期 7 周，约 210 小时。
- 当前优先级：低保真 UI → 单案件灰盒 → 核心规则 → 内容扩展。
- 不得未经批准改变游戏核心命题。
- 不得把游戏简化为“真假二选一”或普通典当店压价游戏。
- 自然语言模型只负责语义映射和文本表现，不负责世界真相、规则结算和最终结局。
- 程序化生成内容必须通过 Schema 与逻辑校验。

## 2. 当前阶段限制

低保真 UI 阶段：

- 不写完整数值系统；
- 不接入生产 API；
- 不生成大量正式资产；
- 不实现完整存档、签到或策展；
- 可以使用占位图、色块、灰盒人物和器物；
- 只验证核心路径、信息层级和交互顺序。

## 3. 架构规则

- UI 不得直接修改 NPC 数值。
- 所有玩家输入统一转换为 `PlayerAction`。
- 规则结算与 UI 渲染解耦。
- 案件内容使用配置数据，不硬编码进组件。
- 物品真相、NPC 认知、NPC 陈述、NPC 状态必须分层。
- Storylet 必须声明触发条件、结果和重复规则。
- NPC 陈述变化必须写入历史，禁止已承认后无条件恢复旧说法。
- 随机行为必须支持固定 seed 复现。
- 关键数值变化必须可输出计算明细。
- 公共 Schema 或接口修改前必须记录迁移影响。

## 4. 推荐职责模式

### 主控 / 集成

- 管理 Sprint；
- 拆解任务；
- 维护公共接口；
- 审核与合并；
- 控制范围膨胀。

### Gameplay Systems

负责：

- Action；
- Evidence；
- NPCState；
- FSM；
- 行为评分；
- Storylet；
- 结局；
- 模拟与测试。

不得：

- 把规则写入 UI；
- 擅自改变产品目标。

### UI / Interaction

负责：

- 竖屏信息架构；
- 观察、证据、询问、对质、交易和复盘页面；
- 动效与状态反馈；
- 可访问性与手机适配。

不得：

- 直接写 NPC 结算规则；
- 为了界面方便绕过 Action 接口。

### Procedural Content

负责：

- Case Schema；
- 生成规则；
- 内容校验；
- 组合器物、来源链、认知和策略。

### Narrative

负责：

- NPC 语言风格；
- Storylet 文本；
- 回访与复盘；
- 结构化事实到自然表达。

不得：

- 修改客观真相；
- 创造 Schema 外的新运行时规则。

### QA / Simulation

默认只读，负责：

- 状态前后矛盾；
- 万能策略；
- 重复刷数值；
- 无解案件；
- 移动端溢出；
- 可复现问题报告。

## 5. 质量规则

每个完成任务必须说明：

1. 完成内容；
2. 修改文件；
3. 验收方式；
4. 测试结果；
5. 遗留风险；
6. 下一步最小任务。

禁止：

- 无关重构；
- 未经批准引入生产依赖；
- 大范围格式化；
- 隐藏不确定性；
- 用临时 Mock 冒充已完成的生产逻辑。

## 6. 文档维护

- 已决定事项写入 `docs/00_PROJECT_KICKOFF.md` 或相关专题文档；
- 未决定事项写入 `docs/11_OPEN_QUESTIONS.md`；
- Sprint 变更写入 `docs/09_SPRINT_PLAN.md`；
- 不要在多个文档维护彼此冲突的同一规则。
