# 《掌眼》项目启动总纲

> 文档状态：Codex 正式启动版  
> 项目类型：2D、手机竖屏 H5 古玩鉴定与交易博弈游戏  
> 计划周期：7 周 × 每周 5 天 × 每天 6 小时，共约 210 小时  
> 当前阶段：低保真 UI 交互原型

---

## 1. 项目一句话定义

《掌眼》是一款以古玩鉴定和交易博弈为核心的 2D 手机策略小游戏。

玩家经营一家古玩店，每天接待携带旧物与不同说辞上门的卖家。玩家需要观察器物、检测细节、整理证据、追问来源，并选择温和、专业或强硬的沟通方式，判断物品的年代、修复情况、来源可信度和交易风险，最终决定正常成交、风险折价、送检后再议、拒绝交易或允许卖家离场。

## 2. 核心设计命题

游戏不是“看表情猜撒谎”，也不是简单回答“真品 / 赝品”。

核心命题是：

> 在有限证据与信息不对称中，玩家如何通过调查、提问和交易条件，把不可验证的故事逐步转化为需要承担成本的承诺。

卖家说错不一定代表故意撒谎。NPC 可能：

- 知道真相并隐瞒；
- 只知道部分事实；
- 真诚相信错误的家族说法；
- 不懂古玩，只希望尽快出售；
- 用真实小瑕疵掩盖更重要的问题；
- 试探玩家是否专业。

因此，玩家判断的是“物品风险 + 卖家认知 + 交易条件”，而不是一个单一真假标签。

## 3. 项目差异化

与普通古董收集、典当店或鉴宝答题游戏相比，《掌眼》的差异点是：

1. **事实、认知与说法分离**  
   物品客观真相、NPC 知道的内容、NPC 说出的内容分别建模。

2. **证据优先于情绪读取**  
   停顿、紧张和回避只是弱信号；物证、陈述变化与有成本承诺才是关键。

3. **沟通态度具有策略代价**  
   温和、专业、强硬不是善恶选择，而是不同阶段的博弈工具。

4. **胜利不是强迫成交**  
   正确拒绝、要求送检或控制风险同样是胜利。

5. **状态驱动叙事，而非大型剧情树**  
   使用固定案件骨架、有限状态机和条件剧情片段 Storylet，避免分支爆炸。

6. **程序化内容与自然语言输入可扩展**  
   运行时逻辑保持结构化；AI 负责内容生产和语义映射，不负责决定世界真相。

## 4. 单局完整流程

### 阶段 0：案件生成（玩家不可见）

系统建立：

- 物品真相：类型、年代、材料、修复、后配、来源链、市场价值；
- NPC 认知：知道、未知、误解、怀疑；
- NPC 目标：急售、试价、欺骗、求证、寻找归宿等；
- NPC 固定参数：性格、抗压、贪婪、急迫、自尊、欺骗能力；
- 案件结构：一个主矛盾、最多一个次矛盾、行动点、Storylet 与结局条件。

原则：先生成事实，再由事实推出可观察线索，不能先随机制造矛盾再强行解释。

### 阶段 1：来客上门

玩家看到：

- 卖家与古玩；
- 初始说辞；
- 开价；
- 当前公开态度；
- 待验证的核心主张。

### 阶段 2：观察与检测

玩家消耗行动点调查：

- 外观；
- 底部或背面；
- 接口与部件；
- 包装；
- 票据；
- 来源照片；
- 图录资料；
- 检测工具。

调查结果进入证据簿，并标记证据强度。

### 阶段 3：选择交互行动

每次交互由四项构成：

- 调查目标；
- 行动类型；
- 表达态度；
- 引用证据。

示例：

```json
{
  "target": "restoration_history",
  "action": "challenge_contradiction",
  "tone": "professional",
  "evidenceIds": ["modern_adhesive_trace"]
}
```

### 阶段 4：系统结算

更新 NPC 四项动态状态：

- 压力 Pressure；
- 信任 Trust；
- 成交意愿 Deal；
- 控制感 Control。

然后根据：

- NPC 固定参数；
- 当前 FSM 状态；
- 已发生事件；
- 玩家证据强度；
- 当前交易条件；

对可执行行为评分。

### 阶段 5：NPC 回应与记录变化

NPC 可执行：

- 直接回答；
- 模糊化；
- 缩小陈述范围；
- 部分承认；
- 否认；
- 降价；
- 转移责任；
- 接受送检；
- 反问；
- 退出。

系统同步记录：

- 已承认事实；
- 已否认事实；
- 陈述版本变化；
- 已拒绝话题；
- 当前报价和交易条件；
- 已触发 Storylet。

### 阶段 6：调查循环

若仍有行动点且案件未强制结算，回到观察或交互阶段。建议单局 2—5 轮。

### 阶段 7：关键对质与谈判

玩家选择：

- 温和试探；
- 专业指出矛盾；
- 强硬揭穿；
- 正常报价；
- 风险折价；
- 检测后付款；
- 直接送检；
- 拒绝；
- 放弃继续追问。

### 阶段 8：结局与复盘

主要结局：

1. 正常成交；
2. 风险折价成交；
3. 送检后再议；
4. 玩家拒绝；
5. NPC 退出。

复盘评价：

- 判断质量；
- 证据质量；
- 交易质量；
- 关系影响。

## 5. 玩家胜利标的

玩家不是追求四项数值越高越好。

胜利定义：

> 最终处置、价格和交易条件与真实风险相匹配，并且判断过程能够由证据解释。

典型最优结果：

| 真实局面 | 合理结果 |
|---|---|
| 真品、风险低、价格合理 | 正常成交 |
| 本体真实但有修复、后配或故事问题 | 风险折价成交 |
| 信息不足但潜在价值较高 | 送检、延迟付款或附条件成交 |
| 价值低、风险过高或明显虚假 | 拒绝 |
| 卖家拒绝合理核验、来源高度可疑 | 结束谈判 |

禁止把“成交率”或“NPC 认错率”作为唯一成功指标。

## 6. NPC 状态系统

### 6.1 四个动态数值

#### 压力 Pressure

NPC 认为自己的说法、利益或安全正在受到威胁的程度。

- 低：放松、主动讲述；
- 中：谨慎、缩小回答范围；
- 中高：让步、改口、降价；
- 极高：强硬对抗或退出。

压力不等于撒谎概率。

#### 信任 Trust

NPC 是否认为玩家专业、公平且值得继续合作。

高信任可解锁：

- 更多来源信息；
- 隐蔽部位检查；
- 私人资料；
- 第三方检测；
- 回访和推荐。

#### 成交意愿 Deal

NPC 当前完成交易的迫切程度。

影响：

- 降价；
- 是否接受延迟付款；
- 是否承担检测成本；
- 高压力下是否仍留下谈判。

#### 控制感 Control

NPC 是否掌握叙事节奏与交易框架。

控制感高：

- 主动讲故事；
- 回避问题；
- 催促成交；
- 用权威或情绪带节奏。

控制感下降：

- 更难回避具体证据；
- 更可能接受玩家提出的条件；
- 需要作出明确承诺。

### 6.2 有限状态机 FSM

宏观状态：

1. Relaxed / 放松；
2. Cautious / 谨慎；
3. Pressured / 受压；
4. Negotiating / 谈判；
5. Exited / 退出。

FSM 负责阶段，连续数值负责细微差异，行为评分负责选择具体回应。

## 7. 数值计算原则

原型公式：

```text
实际变化
= 行动基础值
× 态度倍率
× 证据倍率
× NPC性格倍率
× 当前状态衰减
+ 情境修正
```

### 7.1 初始态度倍率

| 态度 | 压力倍率 | 典型代价 |
|---|---:|---|
| 温和 | 0.75 | 压力较低，信任增加，NPC 控制感可能保留 |
| 专业 | 1.00 | 稳定、证据收益高、适合大多数阶段 |
| 强硬 | 1.25 | 压力和控场效果更强，但损害信任并提高退出风险 |

### 7.2 初始证据倍率

| 证据 | 倍率 |
|---|---:|
| 无证据 / 纯猜测 | 0.50 |
| 弱线索 | 0.75 |
| 中等间接证据 | 1.00 |
| 明确证据 | 1.30 |
| 锚点证据 | 1.60 |

### 7.3 NPC 压力敏感倍率

| 类型 | 倍率 |
|---|---:|
| 抗压 | 0.80 |
| 普通 | 1.00 |
| 敏感 | 1.20 |

### 7.4 状态衰减

压力越高，新增压力收益越低，以防连续强硬成为万能解。

建议原型：

- 当前压力 0—40：1.00；
- 41—70：0.75；
- 71—100：0.50。

### 7.5 调参原则

- 态度决定代价；
- 证据决定效果；
- NPC 性格决定适用对象；
- 当前状态决定边际收益；
- 每个行动只设置一个主要影响、一个次要影响和最多一个风险影响；
- 所有关键数值变化必须可输出计算明细；
- 不能允许重复同一问题无限刷数值。

## 8. Storylet 叙事结构

不为每一种组合编写完整剧情分支。

每个 Storylet 声明：

- 前置条件；
- 互斥条件；
- 优先级；
- 是否可重复；
- 表现文本；
- 状态结果；
- 新信息；
- 解锁行动；
- 写入历史的陈述变化。

示例：

> 当玩家拥有“现代胶痕”证据、压力 ≥ 50、控制感 ≤ 45、成交意愿 ≥ 60，且 NPC 尚未承认修复时，触发“部分承认父亲曾处理过”。

案件采用菱形结构：

```text
多种调查路径
→ 不同证据与状态
→ 核心矛盾收束
→ 关键对质
→ 有限结局
```

## 9. 自然语言输入

### 9.1 定位

自然语言不是自由 AI NPC 对话，而是结构化按钮的参数化输入层。

玩家输入：

> “你说从来没修过，可接口有新胶，怎么解释？”

模型输出：

```json
{
  "target": "restoration_history",
  "action": "challenge_contradiction",
  "tone": "firm",
  "evidenceIds": ["modern_adhesive_trace"],
  "confidence": 0.94
}
```

### 9.2 大模型职责边界

允许：

- 识别调查目标；
- 识别行动类型；
- 识别态度；
- 识别玩家引用的已发现证据；
- 将系统回应润色为人物语气。

禁止：

- 修改物品真相；
- 决定 NPC 数值；
- 决定结局；
- 创造玩家未发现的证据；
- 绕过本地规则；
- 自由扩展运行时语义枚举。

### 9.3 安全回退

- JSON Schema 强校验；
- evidenceIds 必须属于玩家已发现集合；
- 低置信度时让玩家确认解析结果；
- 无效输入映射为澄清或无效交流；
- 固定选项始终保留。

## 10. 程序化案件与资产

### 10.1 案件生成层

结构：

```text
器物原型
+ 真实年代与材质
+ 修复 / 后配状态
+ 来源链
+ NPC认知切片
+ NPC目标
+ NPC策略
+ 市场条件
= 候选案件
```

生成后必须通过：

1. Schema 校验；
2. 状态一致性检查；
3. 可解性检查；
4. 至少两条有效诊断路径检查；
5. 无单一行为线索直接泄题检查；
6. 模拟玩家策略测试；
7. 人工抽查或 Agent QA。

### 10.2 2D 资产管线

推荐视觉结构：

- 固定店铺背景；
- 独立 NPC 胸像；
- 半写实高清古玩主图；
- 独立证据局部特写；
- 程序绘制 UI；
- 纸张、印章、黛青、漆木与朱砂作为视觉语言。

古玩资产：

```text
基础器物
+ 裂纹层
+ 修复层
+ 款识层
+ 后配部件层
+ 污渍与磨损层
```

不要求实时 3D 旋转，采用主视图、底部 / 背面图和关键局部切片。

## 11. 长期留存方向

### 每日

- 开店；
- 昨日检测或交易回执；
- 今日行情；
- 三位来客择一或择二；
- 每日“一眼掌眼”短挑战。

### 中期

- NPC 重复来访；
- 收藏档案补全；
- 店铺风格形成；
- 每周主题策展；
- 周末鬼市或公共案件。

### 长期

- 失散套系重聚；
- 大型来源链调查；
- 地区或器物类别解锁；
- 大型展览。

留存优先依赖：

> 昨天有结果、今天有新事、长期身份在推进。

不以断签惩罚和纯稀有度收集为唯一动力。

## 12. 视觉方向

最终推荐：

> 现代新中式档案 UI + 暗色鉴定工作台 + 半写实古玩切片 + 风格化 NPC 胸像。

### 层级

| 内容 | 精度 |
|---|---|
| 古玩主图、款识、裂纹和修复特写 | 最高 |
| NPC 胸像和状态变化 | 中等 |
| 固定店铺背景 | 中等、少量复用 |
| 票据、旧照片和包装 | 中低、模板化 |
| UI | 清晰、组件化、代码或 SVG 实现 |

### 不推荐

- 纯低分辨率像素风；
- 每个案件一张完整场景插画；
- 高度写实人物摄影；
- 复杂红金古风边框；
- 让 AI 直接生成带文字的最终 UI。

## 13. 技术架构原则

必须分层：

```text
Input Layer
→ Action Parser
→ Rule Engine
→ NPC State / FSM
→ Behavior Scoring
→ Storylet Resolver
→ UI Presentation
```

### 必须遵守

- UI 不直接修改 NPC 数值；
- 规则引擎不依赖渲染框架；
- 案件内容不硬编码在 UI；
- 随机行为可用固定 seed 复现；
- 每个状态变化保留原因日志；
- 自然语言输入可随时替换为固定选项；
- 第一案件必须先以纯数据和文本运行。

## 14. 七周目标

### 目标交付

在 210 小时内争取完成：

- 一套完整核心规则；
- 低保真 UI 与正式竖屏交互；
- 自然语言到 Action 的输入映射；
- 程序化案件 Schema 与生成管线；
- 5—8 个手工精修案件；
- 20 个以上可用程序化日常案件；
- 3—4 个基础器物原型及变体；
- 4—6 种 NPC 原型；
- 基础收藏、资金、回执和人物关系；
- 至少一个长期留存闭环演示；
- 微信内可运行或可部署版本。

### 范围护栏

以下不作为强制承诺：

- 实时多人；
- 无限话题自由对话；
- 复杂跨地区经济模拟；
- 大型在线赛季；
- 数十个完全不同的高精度手工古玩类别；
- 完整商业运营后台。

## 15. 当前下一步：低保真 UI 交互原型

老师当前要求：制作一份低保真 UI 交互界面。

本阶段目标不是做正式美术，而是验证：

1. 玩家是否知道当前要做什么；
2. 器物、NPC、证据和行动如何在手机竖屏中分配；
3. 玩家能否理解发现证据、选择态度、对质与交易的顺序；
4. NPC 状态变化如何反馈；
5. 一局能否在不阅读说明书的情况下顺畅完成。

首个原型案件：

> 民国漆木首饰盒。本体为旧物，经过现代翻修；卖家称“祖传，从未修复”，但对真实年代和修复情况只部分知情。

必须演示的路径：

```text
店铺首页
→ 来客上门
→ 查看器物
→ 检查接口
→ 获得“现代胶痕”
→ 打开证据簿
→ 对照卖家“从未修复”的陈述
→ 选择“专业 + 指出矛盾”
→ NPC 改口
→ 提出送检后付款 / 风险折价 / 拒绝
→ 结算与复盘
```

具体任务见 `docs/06_UI_LOFI_TASK.md`。
