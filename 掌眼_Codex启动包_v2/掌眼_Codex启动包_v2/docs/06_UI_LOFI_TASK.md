# 当前任务：低保真 UI 交互原型

## 1. 目的

在不制作正式美术、不实现完整规则的前提下，验证手机竖屏中的：

- 信息架构；
- 页面顺序；
- 操作理解；
- 证据与陈述对照；
- 态度与行动选择；
- 对质、交易和复盘闭环。

## 2. 画布

建议基准尺寸：

- 390 × 844；
- 同时检查 360 × 800 和 430 × 932；
- 最小可点击区域约 44 × 44；
- 正文不得依赖极小字号。

## 3. 原型案件

### 物品

民国漆木首饰盒。

### 客观真相

- 木胎为旧物；
- 年代为民国晚期；
- 表面经过现代翻修；
- 锁扣后配；
- 底款后刻；
- 卖家父亲在旧货市场购买。

### NPC 认知

- 知道锁扣换过；
- 知道父亲不是祖传获得；
- 不清楚准确年代；
- 怀疑曾经翻新；
- 希望尽快卖出；
- 初期使用“祖传、从未修复”说法抬高价值。

### 主矛盾

“从未修复”与现代胶痕、翻修痕迹冲突。

### 次矛盾

“祖传”与购买票据 / 来源照片时间冲突。

## 4. 必须页面 / 状态

### P0：店铺首页

必须显示：

- 今日营业状态；
- 来客卡片；
- 进入案件按钮；
- 极简资金或声誉占位。

### P1：来客上门

必须显示：

- NPC 占位胸像；
- 古玩缩略图；
- 初始说辞；
- 开价；
- “开始掌眼”。

### P2：器物观察

必须显示：

- 古玩主视图占位；
- 可点击热点；
- 剩余行动点；
- 切换正面 / 底部 / 接口；
- 进入证据簿、行动、交易的入口。

必须互动：

- 点击接口；
- 弹出局部特写；
- 确认获得“现代胶痕”；
- 点击“收进证据簿”后，消耗 1 行动点，同时完成证据收录、关闭特写并返回器物观察；
- 玩家自行选择继续观察、查看证据簿或发起行动。

### P3：证据簿

必须显示：

- 已发现证据；
- NPC 重要陈述；
- 证据与陈述的潜在矛盾；
- 仅提供“返回观察”。

证据簿是只读信息仓库，不承担推进流程的职责。玩家返回 P2 后，只能通过观察页下方的“行动”入口发起对质。

重点验证：

- 玩家是否清楚“现代胶痕”反对“从未修复”。

### P4：选择行动

必须显示：

- 调查目标；
- 行动类型；
- 温和 / 专业 / 强硬；
- 当前引用证据；
- 模糊的风险预告；
- 三种态度初始均不选中，玩家必须主动选择，不以默认值暗示“正确答案”；
- 每次提交将消耗 1 行动点。

核心点击：

- 修复历史；
- 指出矛盾；
- 选择温和 / 专业 / 强硬任一态度；
- 提交。

### P5：NPC 回应

必须按实际提交态度显示：

- 温和：`48/66/69/49`、`relaxed`，不触发 Storylet，NPC 保留“从未修复”原说法，玩家只能回到行动页调整态度后重试；
- 专业：`54/61/66/42`、`cautious`，触发 `partial-restoration-admission`，NPC 改口“至少我接手后没有修过，之前可能处理过。”，可进入交易处置；
- 强硬：`61/48/60/36`、`pressured`，触发 `defensive-restoration-admission`，NPC 防御性改口，可继续推进，但必须呈现关系恶化与离场风险；
- 原陈述与当前陈述对照、玩家当前推断与符合分支的下一步操作。

桌面开发调试栏必须独立显示：

- 压力、信任、成交意愿、控制感的 0—100 精确数值和本次变化；
- 固定 seed、delta 原因、Storylet 阈值和规则处理链；
- “供讨论与调试，不属于玩家界面”的明确标记。

手机 H5 隐藏开发调试栏，不把系统进程塞入玩家页面。

每次从 P4 提交行动均消耗 1 行动点。温和分支返回 P4 后再次提交会继续产生行动点成本。

### P6：对质与交易

必须显示：

- 当前风险摘要；
- 可选结果：
  - 风险折价；
  - 送检后付款；
  - 拒绝；
- 报价 / 条件区域；
- NPC 成交倾向与合作态度。

### P7：结算与复盘

必须显示：

- 最终处置；
- 物品真相；
- 玩家发现 / 忽略的证据；
- 判断质量；
- 证据质量；
- 交易质量；
- 关系影响；
- 下一步回执占位。

### P8（可选）：次日回执

- 检测结果；
- NPC 后续；
- 收藏档案更新。

## 5. 核心可点击路径

```text
P0
→ P1
→ P2
→ 点击接口
→ 获得现代胶痕
→ 收录并消耗 1 行动点后返回 P2
→ P3
→ P4
→ 提交任一态度 + 指出矛盾（消耗 1 行动点）
→ P5
→ 温和：返回 P4 重试
  专业：进入 P6
  强硬：带关系与离场风险进入 P6
→ 送检后付款
→ P7
```

## 6. 原型阶段使用 Mock

可以继续 Mock：

- 证据发现；
- 交易结果；
- 检测回执。

P5 的三种态度、四项数值、阶段变化、Storylet 评估和 NPC 回应均由同一最小规则切片提供；React 与单文件 HTML 应按实际态度读取对应结果。不要把当前工作参数写成最终平衡。

## 7. 验收标准

- 首次体验者能在无口头解释下走完核心路径；
- 任何页面都能说清“我现在在哪、我知道什么、我能做什么”；
- 玩家能理解证据与陈述的矛盾；
- 三种态度看起来是策略工具而非单纯好坏；
- 交易结局不是只有买 / 不买；
- 一局页面不超过必要数量；
- 原型可在老师面前现场点击演示；
- 记录至少 5 条试玩反馈。

## 8. 暂不处理

- 正式配色和插画；
- 自然语言输入；
- 完整数值公式；
- 多案件；
- 程序化生成；
- 签到、策展和经济系统；
- 微信部署。

## 9. 原型后下一步

三态度规则分支完成后：

1. 组织 3—5 人小规模试玩，记录首次态度选择、理解的代价与是否改选；
2. 重点验证温和重试的行动点成本是否清楚，专业是否成为支配策略，强硬风险是否足够可感知；
3. 根据试玩结果决定先调整工作参数，还是扩展第二条证据或第二个 NPC 行为；
4. 在分发入口明确后制作 Web/H5 与 Unity 最小技术样片。
