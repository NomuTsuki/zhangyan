# 七周敏捷开发计划

采用一周一个 Sprint、每周都有可演示版本的轻量敏捷方式。

## Sprint 0：当前低保真原型

- 页面与状态清单；
- 核心可点击路径；
- 老师评审；
- 冻结第一版信息架构。

## 第 1 周：灰盒闭环

- 仓库与工程骨架；
- Action / Evidence / CaseState / NPCState 类型；
- 首个案件纯数据；
- UI 灰盒页面；
- 从开场到结算可运行。

验收：丑但完整。

## 第 2 周：规则引擎

- 四项数值；
- FSM；
- 行为评分；
- Storylet；
- 结局与复盘；
- 调试面板；
- 单元测试。

验收：核心玩法技术闭环。

## 第 3 周：正式 UI 系统

- 竖屏布局；
- 观察、证据、对话、对质、交易；
- 状态反馈；
- 动效框架；
- 多分辨率适配。

验收：第一个案件达到可展示交互质量。

## 第 4 周：内容管线与自然语言输入

- JSON Schema；
- 案件编辑与校验；
- LLM → Action 映射；
- 固定选项回退；
- 低置信度确认；
- API 错误降级。

验收：两种输入方式进入同一规则引擎。

## 第 5 周：内容与资产扩展

- 3—4 个器物原型；
- NPC 原型与状态图；
- 5—8 个精修案件；
- 程序化生成初版；
- 自动逻辑检查。

验收：同一系统产生不同策略体验。

## 第 6 周：长期闭环

- 资金；
- 收藏档案；
- NPC 回访；
- 检测回执；
- 店铺风格；
- 一个每日或策展演示。

验收：单局结果影响后续内容。

## 第 7 周：冻结与交付

- 停止新增功能；
- Bug；
- 调参；
- 微信环境 / 部署；
- 性能与资源；
- 教程；
- 录屏；
- 汇报资料；
- 备份稳定版本。

## 范围调整原则

任何新增功能必须回答：

1. 是否强化核心鉴定与交易博弈；
2. 是否能在当前 Sprint 完成并测试；
3. 是否挤压稳定与交付时间；
4. 是否已有更低成本的演示方式。
