# 《掌眼》低保真 UI 规格草案

> 状态：Sprint 0 可实现草案  
> 基准画布：390 × 844  
> 首案：民国漆木首饰盒  
> 目标：验证观察、证据、对质、交易与复盘是否能在无口头讲解时闭环

## 1. 范围与完成定义

本轮只实现一个案件、一条完整核心路径和三个最终处置选项。证据发现与交易结算仍为明确标注的 Mock；温和、专业、强硬三种行动的 NPC 回应与状态变化均已由同一最小规则切片计算。不实现完整数值平衡、自然语言输入、存档、经济系统和正式美术。

完成时应满足：

- 首次体验者能独立走完核心路径；
- 每屏都能回答“我在哪、我知道什么、我能做什么”；
- 玩家能看懂“现代胶痕”与“从未修复”的矛盾；
- 温和、专业、强硬显示不同收益与风险；
- 最终处置至少包含送检后付款、风险折价和拒绝；
- 360 × 800、390 × 844、430 × 932 三档竖屏均无关键内容溢出。

## 2. 页面与状态清单

### P0 店铺首页

- 页面目的：建立营业日入口和来客选择语境。
- 必须显示：今日营业状态、来客卡片、资金/声誉占位、当前原型说明。
- 可点击操作：接待刘先生。
- 进入条件：启动原型或重新开始。
- 离开条件：选择来客后进入 P1。

### P1 来客上门

- 页面目的：交代人物、器物、初始说辞和开价。
- 必须显示：刘先生占位胸像、首饰盒缩略图、两条初始陈述、Mock 开价。
- 可点击操作：开始掌眼、返回店铺。
- 进入条件：从 P0 接待来客。
- 离开条件：开始掌眼进入 P2；返回进入 P0。

### P2 器物观察

- 页面目的：让玩家理解观察视角、热点和行动点。
- 必须显示：器物占位图、正面/底部/接口切换、剩余行动点、阶段说明、证据簿/行动/交易入口。
- 可点击操作：切换视角、点击接口热点；获得证据后继续观察、打开证据簿或发起行动。
- 进入条件：从 P1 开始掌眼，从 S1 收录证据后返回，或从 P3 返回观察。
- 离开条件：点击接口进入 S1；已有证据时可进入 P3 或 P4。

### S1 接口局部与证据发现

- 页面目的：反馈调查结果并建立“发现证据”的成就感。
- 必须显示：接口局部占位、现代胶痕、证据强度、与修复历史的关联、收录后将消耗 1 行动点。
- 可点击操作：仅“收进证据簿”。
- 进入条件：P2 选择接口并点击热点。
- 离开条件：点击“收进证据簿”后扣除 1 行动点，完成收录、关闭特写并返回 P2，由玩家自行决定下一步。

### P3 证据簿

- 页面目的：作为只读信息仓库，把客观证据与 NPC 陈述并排比较。
- 必须显示：现代胶痕、证据强度、“从未修复”陈述、矛盾关系。
- 可点击操作：仅返回观察。
- 进入条件：P2 在已经收录现代胶痕后打开证据簿。
- 离开条件：返回进入 P2；行动只能从 P2 下方中间的“行动”入口发起。

### P4 选择行动

- 页面目的：组成结构化 PlayerAction，并解释态度的策略代价。
- 必须显示：目标=修复历史、行动=指出矛盾、引用证据=现代胶痕、三种态度及风险提示、“提交消耗 1 行动点”。三种态度初始均不选中，玩家必须主动选择，避免默认值对试玩造成偏置。
- 可点击操作：选择温和/专业/强硬、提交行动、返回观察。
- 进入条件：P2 选择“行动”。
- 离开条件：行动点大于 0 时，任一态度提交均扣除 1 行动点并进入 P5；行动点为 0 时不得提交。

### P5 NPC 回应

- 页面目的：呈现状态变化、陈述版本变化和行动效果。
- 玩家界面必须按态度显示当前阶段、旧陈述与当前陈述对照、当前推断和分支下一步：
  - 温和：`48/66/69/49`、`relaxed`，不触发 Storylet，保留原说法，提供“调整态度，再试一次”；
  - 专业：`54/61/66/42`、`cautious`，触发 `partial-restoration-admission`，部分承认修复可能并可进入交易处置；
  - 强硬：`61/48/60/36`、`pressured`，触发 `defensive-restoration-admission`，防御性改口并可推进，但显示关系受损与离场风险。
- 桌面开发调试栏显示：压力/信任/成交意愿/控制感的规则计算值与变化、固定 seed、delta 原因、Storylet 条件和规则处理链。
- 可点击操作：温和分支返回行动重试；专业/强硬分支进入交易处置；所有分支均可查看证据簿。
- 进入条件：P4 提交“任一态度 + 指出矛盾 + 现代胶痕”。
- 离开条件：温和返回 P4；专业/强硬进入 P6；查看证据进入 P3。

### P6 对质与交易

- 页面目的：把鉴定风险转化为交易条件。
- 必须显示：风险摘要、与态度结果一致的 NPC 合作态度（强硬分支带关系/离场风险）、送检后付款/风险折价/拒绝三个选项、Mock 条件说明。
- 可点击操作：选择处置、确认决定、返回回应。
- 进入条件：P5 处理 NPC 改口。
- 离开条件：确认选择进入 P7。

### P7 结算与复盘

- 页面目的：解释最终结果与真实风险是否匹配。
- 必须显示：最终处置、物品真相、已发现/忽略证据、判断/证据/交易/关系四项评价、次日回执占位。
- 可点击操作：重新体验。
- 进入条件：P6 确认处置。
- 离开条件：重新体验进入 P0。

| P3 | 返回观察 | 已查看证据 | P2 | 回到观察枢纽，不在证据簿推进流程 |
| P2 | 发起行动 | 证据已发现 | P4 | 预填目标、行动与引用证据 |

| P4 | 强硬地指出矛盾 | 引用现代胶痕且剩余行动点 > 0 | P5 | 行动点减 1；输出 `61/48/60/36 + pressured`，触发 `defensive-restoration-admission` |

| P6 | 确认处置 | 已选择一种结果 | P7 | 生成对应 Mock 复盘 |
| P7 | 重新体验 | 无 | P0 | 清空本局原型状态 |

## 4. UI 与未来规则引擎边界

| 原型 UI 负责 | 未来规则引擎负责 |
|---|---|
| 页面导航与操作反馈 | 判断行动是否有效 |
| 展示当前阶段、证据和陈述 | 扣除行动点并验证重复调查 |
| 采集目标、行动、态度和证据 | 计算压力、信任、成交意愿和控制感变化 |
| 玩家界面展示阶段、陈述和可操作结论 | 计算数值变化明细与原因日志 |
| 根据触发结果显示 NPC 回应 | 行为评分、FSM 与 Storylet 解析 |
| 展示三个预设处置结果 | 结局、价格合理度和关系影响结算 |

UI 不直接修改 NPC 数值。当前三种态度均由 `initialState + PlayerAction + seed` 生成新状态、Storylet 评估和事件日志；React 与单文件 HTML 只读取规则输出呈现分支。

开发调试栏是手机画布外的独立侧栏：仅在宽屏演示环境显示精确数值、seed、计算日志和系统进程；窄屏 H5 自动隐藏，避免把开发信息混入玩家体验。

## 5. 当前实现假设

- 最终载体已确认为 H5；当前浏览器原型继续作为正式开发的交互与信息架构基线。
- 当前阶段不验证开价、底价和折价平衡，相关数字继续使用“原型占位”标识。
- NPC 四项状态显示 0—100 规则结算值，优先用于讨论状态变化；当前参数是工作样例，不是最终平衡。
- 视觉采用低保真档案纸与灰盒器物，不引用概念图中的器物名称、年份和价格。
- 首轮三态度已形成可试玩分支：温和不触发 Storylet 并回到行动重试，专业稳定推进，强硬带关系与离场风险推进。
- 收录首条证据和每次提交行动各消耗 1 行动点；温和重试不返还已消耗点数。

## 6. 需要产品或老师确认

已确认最终验收对象是游戏本体，当前优先级依次为：玩法完整度、视觉效果、技术实现、文化内容。Unity 或标准 Web 的实现路线仍需通过低成本技术验证再决定；价格与交易数据暂不进入当前迭代。
