# Codex 自行决策清单

更新时间：2026-07-27

这份文档回答：“哪些东西是你确认的，哪些是 Codex 为了推进原型自己决定的？”

重要说明：自行决定不等于一定错误。问题在于我此前没有始终把“工作样例”与“已获批准的正式规则”标得足够清楚。

## 一、你明确确认过的方向

### 项目与体验

- 最终载体为 H5、手机竖屏；
- 验收材料是游戏本体，老师提供建议和指导；
- 优先级为玩法完整度、视觉效果、技术实现、文化内容；
- 当前先降低不确定性，不急着做价格数据库、大量内容和正式美术。

### 真相、证据与 NPC

- 每件器物有客观真相与量化价值；
- 赝品与珍品应形成较大的价值差异，但极端事件不能成为新手阶段的彩票；
- NPC 有自己的信息差，可能真诚地高估赝品或低估珍品；
- 玩家和 NPC 不故意说谎，但都可以不说；NPC 允许真诚误记和误判；
- 玩家私下证据、NPC 私人认知和双方共享证据应该分层；
- 公开关键证据可能补足证据链，也可能教育 NPC 并改变价格；
- NPC 的专业背景、性格和动机会影响其反应；
- NPC 需要“先发散、再收敛”的有限回应结构。

### 玩家循环

- 检查器物与询问 NPC 不是严格的先后阶段，可以交叉进行；
- 检查和询问可以共享调查预算；
- 行动点耗尽后仍必须能买下或拒绝，不能死锁；
- 证据簿是只读仓库；
- 玩家可以自主报价；
- 系统参考价是保守辅助，不知道隐藏真相，也不保证成交；
- 结算需要区分客观结果与当时判断是否合理。

### 本轮新明确的修正

- 讨价还价不应继续消耗前面的调查行动点；
- 议价次数应由 NPC 设定、性格和玩家此前的演绎结果共同决定；
- 风险转移只是某些情况下可能有效的措施，不是游戏核心；
- 当前客观分定义不合理；
- 当前披露方式难以理解；
- 数值和测试需要渐进式说明。

## 二、Codex 为了让原型运行而自行设定的内容

以下内容没有获得逐项批准。

### 案件工作参数

| 内容 | 当前值 |
|---|---:|
| 真相价值 | 20 / 65 / 130 |
| NPC 初始开价 | 80 |
| 调查行动点 | 6 |

| NPC 初始压力 | 26 |
| NPC 初始信任 | 58 |
| NPC 初始成交意愿 | 72 |
| NPC 初始控制感 | 68 |

### NPC 人物参数

Codex 自行设定了：

- 专业度 `0.62`；
- 真诚敏感 `0.90`；
- 开放度 `0.75`；
- 风险厌恶 `0.72`；
- 急迫度 `0.68`；
- 加价率 `0.08`；
- 外部选项 `15`。

其中“开放度”目前甚至没有真正进入公式。

### 后验与推荐价

Codex 自行决定了：

- 三种真相初始各占三分之一；
- 玩家参考使用 Q20；
- 安全垫为 `max(5, Q50×8%)`；
- 报价按 5 点取整；
- NPC 共享证据按专业度折算。

### NPC 定价

Codex 自行决定了：

- NPC 主观中枢采用 `0.6×Q50 + 0.4×期望值`；
- 风险、急迫度、外部选项和四状态如何进入接受线；
- 普通接受线和无条件买断线的具体公式；
- 正式重估最多发生两次；
- 新报价使用 `10%旧报价 + 90%目标报价`；
- 后验移动 8%、中位数跨档、最可能类型变化或谈判立场变化可触发重估。

### NPC 回应与状态

Codex 自行决定了：

- 温和、专业、强硬分别怎样改变四状态；
- 证据强度如何转换为对峙力度；
- 重复询问的惩罚；
- 合作、回避、承认、反击、拒答、离场的门槛与分项权重；
- seed 对候选行为产生 `±1.5` 的扰动。

### 信息披露

Codex 自行加入了：

- “完整说明事实”；
- “只强调不利部分”；
- 片面披露根据 NPC 专业度和真诚敏感度扣除信任与成交意愿。

你并没有确认这两个抽象按钮应该直接成为玩家动作。

### 议价与风险转移

Codex 自行决定了：

- 每次普通报价消耗 1 个共享行动点；
- 报价与接受线的差额决定接受、还价、拒绝或离场；
- 无条件买断使用独立买断线；
- 买断无论接受或拒绝都立即终局；
- 在实验台和试玩建议中给风险转移过高的关注度。

### 结算

Codex 自行决定了：

- 使用动态买断线构造路径内参考最优（代码称“完全知情可达最优”）；
- 使用后悔值换算 0—100 客观分；
- 70 分作为客观胜利门槛；
- 判断分采用“效用差×3”以及不确定性、无依据风险、重复行动和离场惩罚；
- 把客观成功与判断质量合并成“真正掌眼、侥幸得手”等结局标题。

其中客观分已经被本轮试玩证明存在概念错误。

## 三、Codex 自行做出的技术实现选择

这些主要是可逆的工程选择，不直接等于玩法决定：

- 用 TypeScript 纯规则函数保存世界状态和回放；
- 同时维护 React 开发版和可离线打开的单文件 HTML；
- 把精确公式放在桌面调试栏，手机玩家画布只显示公开结果；
- 使用自动测试验证信息隔离、去重、行动边界和终局；
- 使用固定 seed 复现随机结果；
- 建立数值实验台批量比较不同自动策略。

这里最大的技术债是：TypeScript 与单文件 HTML 仍是两份规则实现，可能随修改产生偏差。

## 五、我本应更早向你确认的事情

1. “客观成功”究竟是盈利、避免损失、压价能力，还是三者组合；
2. 调查预算与议价耐心是否是同一种资源；
3. 玩家通过“选择证据”实现选择性披露，还是还需要额外的措辞按钮；
4. 风险转移是核心循环、人物特技还是少数案件的特殊条件；
5. 哪些公式应该由你先理解并批准，哪些可以仅作为临时测试参数；
6. 回归测试通过只表示代码稳定，不能表示数值合理。
