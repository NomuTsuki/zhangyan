# 回归测试入门：测试通过不等于设计正确

更新时间：2026-07-27

## 一句话解释

回归测试就是：把已经约定过的行为写成可以自动重复检查的例子。以后修改代码时，如果旧行为意外坏掉，测试会立刻报警。

它很像给游戏规则列一份“每次改版都必须重新核对的清单”。

## 一个最简单的例子

假设我们约定：

> 调查行动点为 0 时，不能继续检查，但仍然可以接受当前明示价格或拒绝。

回归测试会自动创建一个行动点为 0 的局面，然后检查：

- 检查按钮对应的规则是否拒绝执行；
- 接受当前明示价格是否仍然可以执行；
- 拒绝是否仍然可以执行；
- 游戏是否能够进入结算。

以后修改行动点代码时，只要破坏其中一个条件，测试就失败。

## 当前34项测试的组成

- 24 项规则核心测试；
- 8 项数值实验台测试；
- 2 项展示与单文件集成测试。

下面按它们保护的行为来解释。

## 当前测试主要在测什么

### 1. 信息隔离

检查：

- NPC 不偷看隐藏真相；
- 玩家私下发现证据不会自动更新 NPC；
- 只有共享证据才更新 NPC 后验；
- 相同可见信息在不同隐藏真相下，NPC 作出相同判断；
- NPC 自己说过的话不会被当成新物证反复教育自己。

它证明的是“信息没有串线”，不证明后验参数合理。

### 2. 证据去重

检查：

- 同一证据不会无限重复增加概率；
- 同一 NPC 回应生成的陈述卡和结构化信号不会计算两次；
- 重复检查会消耗行动点，但不会重复发放证据。

它防止刷分和重复计权，不证明证据内容符合真实鉴定知识。

### 3. 行动与终局边界

检查：

- 行动点不足时，行动失败且不会扣一半资源；
- 0 行动点仍可购买或拒绝；
- NPC 离场后进入结算，而不是停在死页面；
- 买断被接受或拒绝后都能结束；
- 所有自动策略最后都能完成一局。

这里的“边界”就是最容易出现错误的极端状态，例如 0 点、最后一次行动、重复来源和刚好达到阈值。

### 4. 状态连续变化

检查：

- 连续使用同一态度，NPC 状态仍会继续变化；
- 压力、信任、成交意愿和控制感保持在 0—100；
- 行动历史能够完整回放；
- 同一 seed 和同一行动序列得到相同结果。

它证明连续行动时状态会继续变化，不证明变化幅度好玩或真实。

### 5. 定价与交易规则

检查：

- 普通报价使用当前 NPC 接受线；
- 买断使用买断线；
- 达线与未达线分别进入预定分支；
- 价格和 NPC 判断不读取隐藏真相；
- 公开证据可以触发预定的重估。

它证明代码按照当前公式执行，不证明当前公式合理。

### 6. 结算分层

检查：

- 相同真相和成交条件下，获得更多证据只改变判断质量，不改变客观结果；
- 买到赝品和买到珍品的客观结果不同；
- 幸运买中与有证据买中能够显示不同判断质量。

当前测试没有写下：

> 真实价值65、成交价65、检测费0时，客观分不得为100。

因此现有公式即使把零利润评为100，测试仍然可能全部通过。

### 7. 构建与单文件检查

检查：

- React 项目能够编译；
- 单文件 HTML 包含需要的按钮、规则入口和样式；
- 文件不依赖外网也能打开；
- 主要代码没有明显语法错误。

它证明文件能运行，不证明玩家看得懂。

其中单文件 HTML 检查主要确认函数名、按钮文案和脚本结构存在，并不等同于在真实浏览器中逐个点击按钮的端到端测试。

### 8. 数值实验台批量测试

检查：

- 固定 seed 时批量结果可复现；
- 概率归一化；
- 接受、还价、拒绝、离场等分支都能出现；
- 自动策略不会死锁；
- 双方信息不会重复计权或偷看真相。

它证明实验器材可靠，不证明实验中的策略符合真实玩家，也不证明参数已经平衡。

## 为什么这次会出现“34项测试通过，但客观分仍然错误”

因为测试分为两种：

### 代码一致性测试

问题是：

> 代码有没有忠实执行当前公式？

现有测试主要属于这一类。

### 设计正确性测试

问题是：

> 这条公式表达的是不是我们真正想要的游戏目标？

要回答它，必须先由我们共同写出几个正确例子。

这次缺失的不是测试技术，而是“客观分应该代表什么”的共同定义。没有正确答案，测试只能稳定地保护一条错误公式。

## 下一版验证体系应该分成六层

### 第一层：示例测试

先用人能理解的例子约定结果：

- 价值65、总成本65：盈亏平衡，不能是满分；
- 价值65、总成本60：应优于65成交；
- 价值65、总成本55：应优于60成交；
- 同样成交价，多付检测费不能得到更高经营成绩；
- 买到赝品造成亏损，不能因为“已压到底价”而得到客观高分。

### 第二层：单调性测试

不指定每个具体分数，只检查方向：

- 其他条件相同，成交总成本下降，经营成绩不能下降；
- 其他条件相同，真实价值上升，经营成绩不能下降；
- 额外成本上升，净收益不能上升；
- 零利润不能等于目标利润。

### 第三层：边界测试

检查：

- 0 行动点；
- 0 议价容量；
- 刚好达到接受线；
- 比接受线低 1；
- NPC 耐心刚好耗尽；
- 拒绝与离场；
- 费用大于物品价值。

### 第四层：完整场景测试

模拟一条完整路线，检查每一步的证据、状态、议价次数、价格和结算。

### 第五层：平衡模拟

批量运行许多案件，观察：

- 有没有一种策略总是最好；
- 各类 NPC 是否真的需要不同办法；
- 送检、片面披露、强硬压价是否成为支配策略；
- 低、中、高级场的收益与亏损分布是否符合目标。

### 第六层：真人试玩

观察：

- 玩家是否理解系统；
- 玩家是否认为反馈公平；
- 玩家能否解释自己为什么成功或失败；
- 玩家是否感到选择有意义。

自动回归测试不能替代第五层和第六层。

## 一个建议的学习顺序

以后每新增一条规则，可以依次问：

1. 这条规则想表达什么体验？
2. 给出一个最简单的正确例子；
3. 给出一个边界例子；
4. 写成自动测试；
5. 批量观察它是否产生支配策略；
6. 让真人试玩确认反馈是否容易理解。
